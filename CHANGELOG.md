# Журнал изменений

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/). Записи рассчитаны на администратора: что изменилось и что нужно сделать при обновлении.

## [2.5.1] — 2026-10-13

### Добавлено

- В форме отчёта у SQL-списка с множественным выбором над вариантами появился флажок «Выбрать все»: отмечает весь список (без учёта строки поиска), повторное нажатие — «Снять все». Если выбрана часть вариантов, флажок в промежуточном состоянии.

## [2.5.0] — 2026-10-13

### Добавлено

- Нативные диаграммы Word и Excel заполняются данными отчёта: теги ставятся в данные диаграммы строками цикла (`{d.rows[i].m}` и под ней `{d.rows[i+1].m}`) — в Word на листе «Изменить данные», в Excel в ячейках листа. Диапазоны рядов растягиваются на все строки, сохранённые в диаграмме значения пересчитываются (диаграмма верна и в PDF), значения рядов, похожие на число (`1 234,5`, `-3`, `1e3`), становятся числами. Все обычные типы диаграмм, 2D и 3D.
- `:html` — HTML из данных с оформлением в DOCX и ODT (текст, ячейки таблиц, колонтитулы; PDF — из них): абзацы, заголовки, списки с вложенностью, таблицы с `colspan`/`rowspan`, ссылки (проверяются, запасной адрес — `:defaultURL`), изображения `img` (data URI или хост из `IMAGE_URL_ALLOWLIST`), флажки, цвета из `style`, разрывы страниц. Параметры `inline`, `nospace`, `headingtheme`, `tabletheme`, `quotetheme`. В HTML-шаблонах значение вставляется без экранирования.
- В справке по шаблонам новые разделы «Диаграммы» и «HTML».

### Изменено

- `html` больше не даёт «недоступно в бесплатной версии Carbone»: шаблоны с ним формируются. В XLSX, PPTX, ODS, ODP `:html` — ошибка шаблона `400` `CARBONE_TEMPLATE` «html не поддерживается в …».
- Диаграммы Word и Excel с тегами в данных, у которых раньше после сборки диапазоны рядов и сохранённые значения не менялись (диаграмма показывала данные шаблона), теперь строятся по данным отчёта. Шаблоны без диаграмм и без `:html` собираются как раньше.

### Исправлено

- Кнопка «Сохранить» в редакторе шаблона не создавала новую версию, если в OnlyOffice был выбран строгий режим совместного редактирования (браузер запоминает этот выбор): правки не доходили до Document Server, и сохранение ждало подтверждения впустую. Теперь редактор всегда открывается в быстром режиме без переключателя.
- «Сохранить» без правок в редакторе больше не ждёт подтверждения впустую: сразу сообщение «Нет несохранённых изменений» (API — `409` `NO_CHANGES`). Статус каждого callback OnlyOffice пишется в журнал API.

### Ограничения

- Диаграммы: не поддерживаются новые типы Office 2016 (дерево, солнечные лучи, гистограмма распределения, ящик с усами и другие), циклы по столбцам, число рядов из данных, многоуровневые подписи категорий, таблицы Excel и именованные диапазоны (не растягиваются), диаграммы, связанные с внешним файлом, диаграммы PPTX и OpenDocument. Графики ECharts (`:chart`) по-прежнему недоступны.
- `:html`: тег — только в тексте абзаца, `:html` — последний форматтер; значение больше 1 МБ, вложенность глубже 32 или больше 4096 незакрытых тегов — ошибка шаблона; в таблице не больше 63 столбцов; с `inline` внутри гиперссылки шаблона ссылки из HTML становятся текстом; в ODT флажки — символы ☒/☐, `tabletheme` не действует. Классы, `<style>` и прочие свойства CSS игнорируются.
- Вид документов в Word и LibreOffice проверен выборочно: в тестах — структурные проверки и конвертация в PDF через OnlyOffice.

## [2.4.0] — 2026-10-11

### Добавлено

- Изображения из данных: тег, который занимает весь замещающий текст картинки-заглушки (`{d.photo}`), заменяет её изображением из data URI (PNG, JPEG, GIF) или по адресу `http(s)://`. `:imageFit(fillWidth|contain|fill)` задаёт, как вписать изображение в рамку заглушки; пустое значение убирает заглушку. Работает в DOCX, XLSX, PPTX, ODT, ODS, ODP, в том числе в циклах (DOCX — картинка «в тексте», ODT — «как символ»). Лимиты — 10 МБ и 100 млн пикселей на изображение, 50 МБ на отчёт.
- Загрузка изображений по адресу — только с хостов из новой настройки `IMAGE_URL_ALLOWLIST` (по умолчанию пусто — выключено), тайм-аут `IMAGE_URL_TIMEOUT_MS` (5000 мс); в Helm — `config.imageUrlAllowlist` и `config.imageUrlTimeoutMs`. Без перенаправлений, не больше 4 загрузок одновременно на отчёт. Если картинку не удалось загрузить (тайм-аут, ответ не 2xx, размер), она убирается, отчёт формируется, в журнал API пишется предупреждение «изображение не загружено». **Доверие определяется только списком:** не вносите в него хосты, которыми управляют авторы данных.
- Штрихкоды и QR-коды: `{d.code:barcode(qrcode)}` в замещающем тексте картинки-заглушки (типы и опции — как в документации Carbone: `ean13`, `code128`, `datamatrix`…, `width`, `height`, `scale`, `includetext`, `rotate`, цвета, `eclevel`).
- Цвета из данных: `:color(p|cell|row|shape|part, text|background|highlight|border)` в DOCX, PPTX, ODT, ODP.
- Ссылки: адрес гиперссылки из данных проверяется (без схемы — `https://`; допустимы `http`, `https`, `mailto`, `tel`), недопустимый заменяется значением `:defaultURL(...)` или `#`.
- В справке по шаблонам новый раздел «Изображения, штрихкоды, цвета, ссылки»; `pnpm help:check` для примеров с картинкой проверяет, что отчёт собран без ошибки и заглушка заменена.

### Изменено

- Ошибка в теге шаблона (сообщение Carbone с ` Source: "{метка}"`, например неверное изображение, хост вне списка, неверный штрихкод, ошибка `drop`) при формировании и предпросмотре теперь `400` с кодом `CARBONE_TEMPLATE` и текстом «ошибка шаблона: …» вместо `502` `CARBONE_ERROR`. Прочие сбои сборки — по-прежнему `502`. Если ваши интеграции различали ошибки по коду `502`, учтите новый код.
- `color`, `barcode`, `defaultURL` больше не дают «недоступно в бесплатной версии Carbone»: шаблоны с ними формируются. `barcode` в обычном тексте (не в картинке) — ошибка шаблона «штрихкод ставится в замещающий текст картинки».
- Адреса динамических ссылок, которые раньше попадали в документ как есть, теперь проверяются: `javascript:`, `data:`, адреса с `localhost`, IP-адресом или именем хоста без домена верхнего уровня (например, внутренний `http://server:8080`), относительные адреса и якоря (`#раздел`, `../файл.pdf`) становятся `#`. Для внутренних ссылок используйте полное имя хоста. Тег в самом начале адреса (`{d.base}/items/{d.id}`) вставляется как есть, как в 2.3.0; значения тегов после статической части кодируются.
- Замещающий текст картинок из шаблонов 2.3.0 работает как раньше: смешанный текст с тегами («Фото {d.name}») печатается, картинка не меняется и не удаляется; тег, который занимает весь замещающий текст, со значением — обычным текстом (не `data:` и не `http(s)://`) тоже печатается, картинка остаётся. Картинку заменяет только значение-изображение, а пустое значение (`null`, `''`) её убирает.

### Ограничения

- Не поддерживаются: `:autoOrient`, SVG-изображения (ошибка «SVG не поддерживается»), штрихкоды шрифтом, `bindColor` (по-прежнему ничего не красит — используйте `:color`), `failOn`, изображения в HTML-выводе.
- `:color` в XLSX и ODS — ошибка шаблона.
- Несколько изображений в цикле рассчитаны на DOCX (картинка «в тексте») и ODT (привязка «как символ»); картинка с абсолютной позицией (XLSX, PPTX, ODS, ODP) при повторе циклом не сдвигается — копии ложатся на место заглушки.
- Ссылки через поле Word `HYPERLINK` и форма EE для XLSX без фигурных скобок (`d.url`) не проверяются. В адресе со статической частью (`https://site.ru/?id={d.id}`) значение тега после статической части кодируется, а сохраняется весь адрес (в Carbone EE — только динамическая часть).
- Изображения и штрихкоды на реальных Word, LibreOffice и OnlyOffice проверены выборочно: в тестах — структурные проверки документа и конвертация в PDF через OnlyOffice.

## [2.3.0] — 2026-10-10

### Добавлено

- Перенос шаблонов между средами: «Выгрузить» в списке шаблонов (с выбором флажками) и в карточке шаблона создаёт архив `.crt.zip`, «Загрузить из архива» применяет его в другой среде. Переносятся файл, описание, формат по умолчанию, публичность, категория, группы, запросы, параметры; пароли и CA источников данных, идентификаторы и история запусков не переносятся. Источник данных ищется по имени, иначе выбирается в окне загрузки; при совпадении имени шаблона — «обновить» (новая версия, история запусков сохраняется), «копия» или «пропустить». Загрузка выполняется одной транзакцией. Подробности и лимиты — в README, «Перенос шаблонов между средами». Выгрузка доступна в режиме обслуживания, загрузка нет.

### Изменено

- Изменение доступа к шаблону (публичность, категория, группы) теперь обновляет время изменения шаблона: по нему загрузка из архива определяет, что шаблон изменился после предпросмотра.
- nginx: на маршрутах `/api/templates/import*` разрешены тела запроса до 51 МБ (на остальных `/api/` — по-прежнему 25 МБ). Со своим ingress или прокси поднимите лимит тела для `/api/templates/import*` не меньше чем до 51 МБ.

### Исправлено

- Шаблон, где в строке-разделителе `[i+1]` стоит метка `[i]` (например, `{d.cars[i].qty}`), а дальше идёт вторая таблица или абзацы по тому же массиву, давал пустой документ без ошибки. Теперь рендер останавливается с ошибкой `The marker … is in the [i+1] row of array "…"`: в строке `[i+1]` оставьте только метки `[i+1]` или пустые ячейки. Carbone EE на таком шаблоне выводит таблицы с повторами.

### Ограничения

- Если во время загрузки шаблонов кто-то вручную создаёт шаблон с тем же именем, возможен дубль имени.

## [2.2.0] — 2026-10-10

### Добавлено

- Агрегаторы Carbone в шаблонах: `aggSum`, `aggAvg`, `aggMin`, `aggMax`, `aggCount`, `aggCountD`, `aggStr`, `aggStrD` (итог по всему набору или по отобранным элементам, подытог по вложенному массиву) и `cumSum`, `cumCount`, `cumCountD` (нарастающий итог по строкам цикла), в том числе с группировкой `aggSum(.поле)`. `:count()` нумерует строки цикла 1, 2, 3… без пропусков при фильтре. Раньше такие шаблоны не формировались («недоступно в бесплатной версии Carbone»). Подытоги по группам собираются в шаблоне через `:set` и `aggSum`. В справке по шаблонам новый раздел «Итоги и нумерация» и пример «Подытоги по группам (:set)», примеры проверены на нашей сборке.
- `drop` и `keep`: удаление абзаца, строки, столбца, таблицы, рисунка, диаграммы, фигуры (в ODS — листа, в ODP — слайда) по условию, например `{d.f:ifEQ(true):drop(p)}`, `{d.cars[i].ok:ifEQ(false):drop(row)}`; `drop(p, 3)` и `drop(row, 3)` убирают несколько подряд. Без условия решает само значение: удаляют `true`, ненулевое число, непустой текст, кроме `"0"` и `"false"`; флаги 0/1 из БД работают как есть (`{d.rows[i].archived:drop(row)}`). Работают в DOCX, ODT, XLSX, ODS, PPTX, ODP; в справке по шаблонам — примеры в разделе «Условия».

### Ограничения

- XLSX: `drop(col)` не пересчитывает объединённые ячейки, автофильтр и условное форматирование; на листе с форматированной таблицей («Форматировать как таблицу») `drop(col)` — ошибка шаблона.
- `cumSum`, `cumCount`, `:count()` и итоги по `[]` считают и строки, удалённые `drop(row)`: чтобы строка не попала ни в нумерацию, ни в итог, отбирайте строки фильтром цикла.
- Итоги с фильтром в скобках (`{d.rows[ok=true].qty:aggSum}`) на десятках тысяч строк считаются секунды: на таких объёмах считайте их в SQL.
- `drop`/`keep` не работают во вложенных файлах (данные диаграмм); `drop(col)` не поддерживается в таблицах с горизонтально объединёнными ячейками.
- Сортировка по убыванию (`[-qty, i]`) в Carbone пока не реализована и в 2.2.0 не добавлена: сортируйте в SQL (`ORDER BY … DESC`).

## [2.1.1] — 2026-10-10

### Исправлено

- XLSX-отчёты, которые Document Server преобразует в другой формат (PDF, ODS), теряли весь текст ячеек, кроме первой текстовой ячейки листа. Ошибка была с версии 2.0.0; сам XLSX без преобразования всегда был корректным. Теперь текст ячеек пишется в общий словарь строк (`sharedStrings.xml`), а строкам и ячейкам возвращаются номера.

Действий при обновлении не требуется: настройки и данные не меняются.

## [2.1.0] — 2026-10-10

### Добавлено

- Версия сборки. В подвале боковой панели появился пункт «Версия X»; по щелчку открывается окно «О программе»: версия, коммит и дата сборки интерфейса, версия и коммит сервера, лицензия. Если версии интерфейса и сервера различаются, окно предупреждает об этом (обычно помогает обновить страницу или проверить развёртывание).
- `GET /api/version` — версия, коммит и дата сборки сервера; только для вошедших пользователей, без сессии — 401.
- Образы api, web и backup принимают аргументы сборки `APP_VERSION`, `APP_COMMIT`, `APP_BUILD_DATE` (CI передаёт их сам; без них образ считается `dev`); API и агент бэкапа пишут версию в журнал при запуске.
- `CHANGELOG.md` и выпуск на GitHub: по тегу `vX.Y.Z` CI создаёт релиз с текстом раздела из этого файла. Тег без раздела в CHANGELOG не публикуется.

### Изменено

- Проект распространяется по лицензии PolyForm Strict 1.0.0 (тексты — `LICENSE.md` и `NOTICE.md` в корне репозитория): использование без изменений в некоммерческих целях; остальное — по отдельному договору. `packages/carbone` по-прежнему под CCL. Файлы лицензии лежат в образах, у образов метка `org.opencontainers.image.licenses`.

Действий при обновлении не требуется: настройки и данные не меняются.

## [2.0.2] — 2026-10-10

### Исправлено

- Массивы строк в циклах: `null` и объект в массиве дают строку цикла с пустым значением (`ifEmpty` срабатывает), `[null]` — одну пустую строку, как в Carbone EE. Раньше строка пропадала.
- `{d.list[i]}` без форматтеров на массиве объектов, если абзац состоит только из этой метки, даёт пустую строку, а не исчезает.

### Изменено

- Helm: пауза `api.preStopSleepSeconds` (5 с по умолчанию) перед SIGTERM — запросы первых секунд остановки не получают отказ соединения.

## [2.0.1] — 2026-10-09

### Добавлено

- Плавная остановка API: по SIGTERM `/api/ready` отвечает 503, API ждёт активные отчёты (до `max(RENDER_TIMEOUT_MS, REPORT_TIMEOUT_MS)` + 5 с) и только потом закрывает соединения. В Helm согласован `terminationGracePeriodSeconds`, в compose задан `stop_grace_period`.

### Изменено

- В режиме обслуживания работают разовые ссылки `/internal/render-files`, поэтому конвертация в PDF не обрывается.
- Поток рендера, зависший при загрузке, пересоздаётся по сроку готовности.

### Исправлено

- Шаблоны с парой `hideBegin`/`hideEnd` на границе строки `[i+1]` больше не дают ошибку (шаблоны, собиравшиеся без ошибки, собираются как раньше).
- `CONVERT_ERROR` при SIGTERM во время конвертации.

## [2.0.0] — 2026-10-09

### Несовместимые изменения

- **Контейнера Carbone больше нет.** Отчёты собирает API встроенной сборкой Carbone Community Edition 3.8.2 (`packages/carbone`, воркеры `worker_threads`). Переменная `CARBONE_URL` не читается, том шаблонов Carbone не нужен, блок `carbone:` в values чарта Helm удалён.
- **OnlyOffice обязателен для любого отчёта:** PDF и перевод в ODT/ODS делает Document Server. Вёрстка PDF может немного отличаться от отчётов 1.x (там конвертировал LibreOffice).
- **`API_SELF_URL`:** Document Server забирает файлы у API по одноразовой ссылке. В compose и Helm значение по умолчанию подходит; в Helm используется IP пода (рассчитано на IPv4), внешний Document Server должен достигать IP подов API.
- Helm: лимит памяти `api.resources` — не менее 2Gi (новое значение по умолчанию; `requests` — 500m / 512Mi).
- Поведение шаблонов, как в Carbone EE: `ifEmpty` не обрывает цепочку форматтеров; аргумент в кавычках, начинающийся с точки (`:formatN('.x')`), — строка, а не путь к данным; ошибка вместо молчаливой сборки у шаблонов с `hideBegin` в конце строки (снято в 2.0.1).

Порядок обновления с 1.x — в README, раздел «Обновление с 1.x»: бэкап, `docker compose up -d --no-build --remove-orphans`, удаление тома `<проект>_carbone_templates`, очистка `CARBONE_URL` и ключей `cr:carbone:tpl:*` в Redis (по желанию). Шаблоны и отчёты в S3 не меняются.

### Добавлено

- Пул воркеров рендера: `RENDER_WORKERS` (по умолчанию `min(4, число ядер)`), `RENDER_TIMEOUT_MS`, предел кучи потока `RENDER_WORKER_MEMORY_MB` (по умолчанию из лимита памяти контейнера; в Helm `config.renderWorkerMemoryMb`).
- Синтаксис бесплатного режима Carbone 5: итератор `.i`, циклы по массивам строк, `:set`, новые форматтеры; отключённые платные функции дают ту же ошибку, что и EE. Платные функции Carbone EE (например, `aggSum`) не поддерживаются.
- Проверка сборки в CI с настоящим Document Server и smoke в kind (рендер PDF и DOCX).
