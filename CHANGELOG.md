# Журнал изменений

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/). Записи рассчитаны на администратора: что изменилось и что нужно сделать при обновлении.

## [2.12.0] — 2026-10-21

### Добавлено

- Роль «Редактор» (`editor`): создаёт шаблоны (пустые, из файла, импортом) и становится их владельцем; правит свои и выданные ему шаблоны, смотрит превью, назначает им категорию, группы и «Доступно всем». В разделе «Шаблоны» видит только свои и выданные. Строит отчёты как обычный пользователь: превью доступно без групп, построение — только при доступе по группам или категории. Источник данных выбирает из списка (`GET /api/datasources/options`), настроек подключения не видит; в архиве, который выгружает редактор, у источника только имя (архив загружается как обычно, источник сопоставляется по имени). Выданный шаблон удалить не может; при импорте обновляет только свои и выданные шаблоны, отсутствующие категории не создаются.
- Владелец шаблона и редакторы: владелец или администратор выдаёт право правки на вкладке «Настройки» → «Редакторы» (только пользователям с ролью «Редактор»), администратор может «Сменить владельца».
- Роль «Распорядитель доступа» (`access_manager`): разделы «Группы», «Категории» и «Доступ к отчётам» (все шаблоны: имя, категория, группы, «Доступно всем»; содержимого шаблонов он не видит). Ведёт состав групп. Отчёты строит как обычный пользователь.
- `LDAP_DEFAULT_ROLE` принимает все четыре роли (`admin`, `editor`, `access_manager`, `user`). Первый вход по OIDC по-прежнему создаёт `user`.

### Изменено

- Миграция `0015`: `templates.owner_id` (при удалении пользователя становится пустым) и таблица `template_editors`. Применяется при старте API автоматически.
- Администратор по-прежнему не может изменить собственную роль; правило теперь действует для любой другой роли, включая новые.

### Обновление

- Шаблоны, созданные до 2.12.0, не имеют владельца: редактор их не видит, правит только администратор, пока не назначит владельца или редакторов.
- Распорядитель доступа ведёт состав групп и поэтому может включить в любую группу себя и получить доступ к построению любого отчёта. Выдавайте эту роль с учётом этого.
- Редактор может выполнять любые SELECT-запросы к любому источнику данных из списка (запросы шаблона и их пробный запуск) с правами учётной записи источника; настройки подключения при этом скрыты. Выдавайте роль с учётом этого.
- Если у редактора забрали право правки или понизили роль, пока у него открыт документ в OnlyOffice, редактор документа закрывается, а присланные после этого сохранения отклоняются: файл шаблона не меняется, у шаблона — ошибка сохранения «изменения не сохранены: нет права на правку шаблона».
- Откат на 2.11.x: перед ним смените роли `editor` и `access_manager` на `admin` или `user` — 2.11 этих ролей не знает. Владельцев и редакторов шаблонов 2.11 просто игнорирует.

## [2.11.0] — 2026-10-20

### Добавлено

- Подпись отчёта по ГОСТ Р 34.10-2012 через КриптоПро ЭЦП Browser plug-in: ключ остаётся на компьютере пользователя, сервер получает хеш PDF (Стрибог) и подпись, проверяет её своей реализацией ГОСТ и сохраняет PDF со штампом и открепленную подпись CAdES. Способ выбирается в шаблоне («Способ подписи»: `.p12` или ГОСТ); `POST /api/runs/:id/sign/gost/prepare` и `/complete`.
- `SIGN_GOST_TSA_URL` (Helm — `config.signGostTsaUrl`): служба меток времени для подписи по ГОСТ (CAdES-T); пользователь обращается к ней со своего компьютера.
- Скачивание подписи: `GET /api/runs/:id/file?format=sig`; в окне подписи и «Моя подпись» — проверка плагина.
- Страница `/cadesplugin_api.js` и каталог `./cades/` (Helm — `web.cadesPluginConfigMap`) для скрипта КриптоПро; инструкция — `docs/operations/gost-signature.md`.

### Изменено

- Миграция `0014`: `report_run_signatures.method` (существующие подписи получают `'p12'`) и `sig_path`, `report_runs.sign_method` (способ подписи из снимка; прежним запускам с подписью в шаблоне проставляется `'p12'`), таблица `gost_sign_pending`.
- `RunSignature.method` (`p12` | `gost`) и `RunDto.signMethod`. Запуски и шаблоны без способа подписи работают как `.p12`.
- Сервер не проверяет цепочку сертификатов, отзыв и сертификат службы меток; время метки справочное и принимается только в окне от подготовки (минус 5 минут) до завершения (плюс 5 минут). Подлинность подтверждает сервис проверки (Госуслуги).

### Обновление

- Docker: при первом обновлении выполните `docker compose up -d` (а не только перезапуск контейнеров) — `web` получает новое монтирование `./cades`.
- Для подписи по ГОСТ скачайте `cadesplugin_api.js` с сайта КриптоПро и положите в `./cades/` (Helm — ConfigMap и `web.cadesPluginConfigMap`); перезапуск `web` не нужен для Docker. Без файла всё работает как раньше, а окно подписи по ГОСТ сообщает, что плагин не найден.

## [2.10.2] — 2026-10-20

### Добавлено

- В редакторе шаблона предупреждение о тегах, где русская буква стоит среди латинских (например, «с» в `{d.data[].сnt}` или `{с.g[i].cnt}` вместо `c`): такие теги не находят данные. Показывается над вкладками и обновляется после загрузки, замены и сохранения файла; `GET /api/templates/:id/tag-warnings`.

### Исправлено

- XLSX: пустые ячейки и строки, которых нет в файле шаблона (Excel не сохраняет пустые ячейки без оформления), больше не сдвигают соседние — например, итоги `aggSum` под таблицей при пустой первой ячейке строки съезжали на столбец влево.
- XLSX: объединённые ячейки следуют за строками при циклах — объединение под таблицей сдвигается вместе со строкой итогов, объединение в строке цикла повторяется в каждой строке данных, объединение в удалённой строке (`[i+1]`, `drop`) убирается. Раньше оно оставалось на месте и закрывало строку данных.

## [2.10.1] — 2026-10-20

### Исправлено

- Повторно присланный back-channel logout token (тот же `jti`) больше не завершает сессии, открытые после первого выхода; если отзыв не записался из-за сбоя базы, повторная доставка того же токена (если провайдер её делает) его выполняет.
- Вход через Keycloak в `ADMIN_LOGIN` и в занятый логин отвечают одинаково — `403 OIDC_LOGIN_UNAVAILABLE` «вход через Keycloak для этой учётной записи недоступен — обратитесь к администратору»; причина — в журнале API. Коды `OIDC_ACCOUNT_RESERVED` и `OIDC_ACCOUNT_LINK_REQUIRED` в ответе входа больше не используются.
- Пробелы по краям логина при входе отбрасываются: `ivanov` входит в аккаунт `ivanov` (локально и через LDAP), отдельный аккаунт не заводится.
- При `COOKIE_SECURE=true` cookie сессии называется `__Host-session`, cookie входа через Keycloak — `__Secure-oidc_flow`: cookie сессии нельзя подставить ни с поддомена, ни по http, cookie входа — по http.
- Журнал запросов не пишет query у адресов OIDC и в процент-кодированном виде (`/api/auth/%6fidc/callback?code=…`).
- Администратор, вошедший через Keycloak, после изменения своей записи (пароль, роль) сохраняет привязку сессии к Keycloak: выход через Keycloak и back-channel logout её завершают (ошибка 2.10.0).
- Подпись: окно лимита неверных паролей считается по часам базы данных, а не API; срок разбора `.p12` при загрузке отсчитывается от начала запроса; ответ потока при разборе `.p12` проверяется.

### Обновление

- При `COOKIE_SECURE=true` после обновления всем пользователям нужно один раз войти заново: прежняя cookie `session` не принимается. При нескольких репликах API (Helm) повторный вход может потребоваться до завершения выката. При `COOKIE_SECURE=false` ничего не меняется.
- Если интеграции разбирали коды ошибок входа через Keycloak, замените `OIDC_ACCOUNT_RESERVED` и `OIDC_ACCOUNT_LINK_REQUIRED` на `OIDC_LOGIN_UNAVAILABLE`.

## [2.10.0] — 2026-10-20

### Добавлено

- Вход через Keycloak и другие провайдеры OpenID Connect (authorization code + PKCE). По умолчанию выключен (`OIDC_ENABLED=false`); кнопки на странице входа нет — вход начинается с адреса `/api/auth/oidc/login`. Пользователь сопоставляется по паре `issuer` + `sub`; первый вход заводит пользователя с ролью `user`; при совпадении логина с существующим аккаунтом нужна явная привязка администратором (`POST /api/admin/auth/oidc/identities`). Выход через Keycloak и back-channel logout. Настройка — `docs/operations/keycloak.md`.
- `LDAP_LOGIN_ATTRIBUTE` (необязательно): атрибут записи каталога, значение которого становится локальным логином (OpenLDAP — `uid`, AD — `sAMAccountName`). Нужен при фильтре по нескольким атрибутам, например вход по логину или по почте в один аккаунт. Не задан — как раньше, локальный логин тот, что введён.

### Изменено

- Логин пользователя уникален без учёта регистра (миграция 0013).
- Встроенный `ADMIN_LOGIN` недоступен через LDAP в любом написании и через Keycloak.
- Аккаунт, заведённый первым входом через Keycloak, входит только через Keycloak (новое поле `users.auth_source`).
- Новые переменные окружения: `OIDC_ENABLED`, `OIDC_ISSUER`, `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET`, `OIDC_REDIRECT_URI`, `OIDC_POST_LOGOUT_REDIRECT_URI`, `LDAP_LOGIN_ATTRIBUTE` (см. `.env.example`). При `OIDC_ENABLED=true` обязательны HTTPS-адреса и `COOKIE_SECURE=true`. В Helm — через `api.extraEnv` (секрет клиента — из Secret).
- Новая зависимость API: `openid-client`.

### Обновление

- Перед обновлением проверьте, нет ли логинов, отличающихся только регистром (`Ivan` и `ivan`): миграция 0013 в этом случае остановится со списком таких логинов, и API не запустится. Запрос для поиска и порядок действий — в `docs/operations/keycloak.md`, раздел «Проверки и откат».
- Без `OIDC_ENABLED=true` и без `LDAP_LOGIN_ATTRIBUTE` вход работает как раньше.

## [2.9.1] — 2026-10-20

### Изменено

- Разбор файла сертификата `.p12` выполняется в пуле рендера и не блокирует API.
- Вторая одновременная подпись того же пользователя сразу получает `409` «другая подпись уже выполняется — повторите через несколько секунд»: без ожидания и без занятия соединения.
- Счётчик неверных паролей подписи хранится в базе (таблица `sign_password_failures`, миграция 0012): он одинаков для всех экземпляров API и не зависит от Redis.

## [2.9.0] — 2026-10-20

### Добавлено

- Электронная подпись PDF (PAdES): отчёт подписывает сам пользователь своим сертификатом из файла `.p12`/`.pfx` (RSA от 2048 бит, ECDSA P-256/P-384). Это усиленная неквалифицированная подпись; ГОСТ-сертификаты (КриптоПро) пока не поддерживаются.
- Страница «Моя подпись» для всех пользователей: загрузка, замена и удаление сертификата, предупреждение за 30 дней до окончания срока. Администратор видит срок сертификата в списке пользователей и может удалить сертификат пользователя.
- Блок «Электронная подпись» на вкладке «PDF» шаблона: «Разрешить подпись PDF» и положение штампа. Несовместим с паролем и запретами, с PDF/A совместим; переносится с шаблоном и копируется при «Дублировать».
- «Подписать PDF» на странице отчёта и «Подписать…» в истории; внизу последней страницы (слева, по центру или справа) ставится видимый штамп 250 × 80 пт (оставьте внизу страницы 110 пт). «Скачать подписанный PDF» и «PDF с подписью» в истории. Пароль к ключу вводится при каждой подписи и нигде не хранится; неверный пароль — не больше 5 раз за 15 минут.
- Необязательная метка времени RFC 3161 от службы, заданной администратором.
- Раздел «Электронная подпись» в справке по шаблонам.

### Изменено

- Новые переменные окружения: `SIGN_TSA_URL` (адрес службы меток времени, `http`/`https`; по умолчанию пусто — подпись без метки; неверный адрес — API не запускается) и `SIGN_TSA_TIMEOUT_MS` (по умолчанию `10000`, 1000–60000). В Helm — `config.signTsaUrl` и `config.signTsaTimeoutMs`. Службе меток нужен исходящий доступ из API; NetworkPolicy чарта не меняется (исходящий трафик не ограничен).
- Новые зависимости API: `pkijs`, `asn1js`, `node-forge` (лицензии — в `NOTICE.md`).

### Обновление

- При обновлении применяется миграция `0011` (таблицы `user_certificates` и `report_run_signatures`, колонка `report_runs.signature_position`); существующие данные не меняются, действий не требуется.

## [2.8.1] — 2026-10-16

## [2.8.0] — 2026-10-16

### Добавлено

- Блокировка редактирования шаблона: документ правит один человек, остальные открывают его только для просмотра и видят правки на лету. Блокировка продлевается, пока вкладка открыта, и снимается сразу при закрытии вкладки или уходе со страницы шаблона (после аварийного закрытия — примерно через минуту).
- «Забрать редактирование» (перехват) с подтверждением; у прежнего редактора появляется сообщение «Редактирование забрал …».
- Развёрнутый режим редактора («Развернуть»/«Свернуть») на весь экран.
- Панель тегов: поиск, сворачивание, перетаскивание тегов мышью прямо в документ.
- «Конструкции» — готовые заготовки для условий и циклов, тоже перетаскиваются в документ.
- Метка «Редактирует …» в списке шаблонов.
- Предупреждение в окне загрузки из архива: шаблон для обновления сейчас редактируют.

### Изменено

- `GET …/editor-config` требует параметр `holder`, `POST …/save` принимает тело `{ holder }`.
- Замена файла отклоняется с `409`, если шаблон редактирует другая вкладка; со страницы шаблона, которая сама держит блокировку, файл заменить можно (`PUT …/file` принимает необязательный `?holder=`). Удаление шаблона и импорт с действием `update` при любой открытой правке отклоняются с `409`.
- После обновления перезагрузите открытые вкладки редактора шаблонов: старая страница не передаёт `holder` и получит `400`.
- При обновлении применяется миграция `0010` (блокировки редактирования шаблонов).

## [2.7.1] — 2026-10-15

### Добавлено

- Блок «Защита» на вкладке «PDF»: пароль на открытие и запреты печати, копирования текста и изменения (AES-256). Пароль хранится зашифрованным и в интерфейсе не показывается.
- Запреты переносятся между средами и копируются при «Дублировать» вместе с паролем; при импорте в другую среду пароль не переносится — окно загрузки предупреждает об этом.

### Изменено

- Образ API: добавлен `qpdf` (Debian bookworm), 395 → 399 МБ. Без `qpdf` API запускается, но отчёты с паролем или запретами получают ошибку 503 — при сборке своего образа установите пакет `qpdf`.
- При обновлении применяется миграция `0009_pdf_password` (колонка пароля PDF; существующие данные не меняются).

### Ограничения

- Пароль на открытие — 4–64 символа, не начинается с «-».
- PDF/A и защита несовместимы.
- Защита действует на PDF сформированных отчётов; предпросмотр администратора и «Сохранить как DOCX/XLSX…» — без неё. PDF уже сформированных отчётов при смене пароля не меняется.
- Электронная подпись — в 2.7.2.

## [2.7.0] — 2026-10-15

### Добавлено

- Вкладка «PDF» в редакторе шаблона: PDF/A-2b, водяной знак, сквозная нумерация страниц, метаданные (название, автор, тема, ключевые слова) и приложенные PDF-файлы шаблона в начале или в конце отчёта.
- Теги `{d.поле}` в водяном знаке и метаданных: «ЧЕРНОВИК» только у неутверждённых документов, номер документа в названии PDF.
- Настройки PDF и приложенные файлы переносятся между средами и копируются при «Дублировать».

### Изменено

- PDF с настройками собирается в два шага: OnlyOffice переводит отчёт в PDF (или PDF/A), затем API добавляет приложения, водяной знак, нумерацию и метаданные. Шаблоны без настроек PDF собираются как раньше.
- Образ API: 369 → 395 МБ (`pdf-lib`, `@pdf-lib/fontkit`).
- При обновлении применяется миграция `0008_pdf_options` (колонка настроек PDF и таблица приложенных файлов; существующие данные не меняются).

### Ограничения

- Настройки действуют только на PDF; «Сохранить как DOCX/XLSX…» — без них.
- PDF/A — уровень 2b; приложенные файлы при PDF/A должны быть в PDF/A (признак из метаданных файла).
- В полях PDF — только теги без форматтеров; символы вне шрифта PDF (эмодзи, иероглифы) из данных заменяются на «?».
- Пароль и ограничения на PDF — в 2.7.1, электронная подпись — в 2.7.2.

## [2.6.0] — 2026-10-14

### Добавлено

- Графики ECharts: тег `{d.x:chart}` в замещающем тексте картинки-заглушки рисует график ECharts 5 в DOCX, XLSX, PPTX, ODT, ODS, ODP (PNG, размер — картинка-заглушка или `width`/`height`). Значение — `{ type, option }` или описание ECharts с `series`, строка JSON тоже подходит; `theme: "dark"` или объект темы.
- Конструктор графиков — вкладка «Графики» в редакторе шаблона: столбцы, горизонтальные столбцы, линии, области, круговая, кольцевая, комбинированная; ряды из колонок или из данных; заголовок, легенда, палитры, оси, формат чисел; предпросмотр на тестовых данных. Описания графиков попадают в данные отчёта как `d.charts.<ключ>`, теги показываются на вкладке «Документ».
- Графики переносятся вместе с шаблоном (архив переноса, поле `charts`).
- В справке по шаблонам — раздел «Графики ECharts».

### Изменено

- `chart` больше не даёт «недоступно в бесплатной версии Carbone»; тег `:chart` в обычном тексте — ошибка шаблона `400` `CARBONE_TEMPLATE` «график ставится в замещающий текст картинки».
- Ключ запроса `charts` в шаблоне с графиками занят (`400` `VALIDATION`), запрос, по которому строится график, нельзя удалить или перевести в «Одна строка».
- Образ API больше примерно на 62 МБ (307 → 369 МБ): ECharts, resvg-js и шрифты Noto Sans.
- При обновлении применяется миграция `0007_template_charts` (новая таблица, существующие данные не меняются).

### Ограничения

- Описание графика — до 1 МБ, до 20 рядов и 10 000 точек, отрисовка до 5 с; функции в описании не работают (только JSON); шрифт — только Noto Sans, другие семейства шрифтов из описания рисуются Noto Sans; картинки в описании (`graphic`, `symbol: 'image://…'`, узоры, ключи `image`) — только `data:image/png|jpeg|gif;base64,…`, другие (адреса, пути к файлам, SVG) — ошибка шаблона; PNG — в 2 раза больше логического размера, если стороны не больше 2000 px, иначе в масштабе 1; подписи-даты в графиках конструктора — без перевода часового пояса. Графиков в шаблоне — до 20.

## [2.5.0] — 2026-10-13

### Добавлено

- Нативные диаграммы Word и Excel заполняются данными отчёта: теги ставятся в данные диаграммы строками цикла (`{d.rows[i].m}` и под ней `{d.rows[i+1].m}`) — в Word на листе «Изменить данные», в Excel в ячейках листа. Диапазоны рядов растягиваются на все строки, сохранённые в диаграмме значения пересчитываются (диаграмма верна и в PDF), значения рядов, похожие на число (`1 234,5`, `-3`, `1e3`), становятся числами. Все обычные типы диаграмм, 2D и 3D.
- `:html` — HTML из данных с оформлением в DOCX и ODT (текст, ячейки таблиц, колонтитулы; PDF — из них): абзацы, заголовки, списки с вложенностью, таблицы с `colspan`/`rowspan`, ссылки (проверяются, запасной адрес — `:defaultURL`), изображения `img` (data URI или хост из `IMAGE_URL_ALLOWLIST`), флажки, цвета из `style`, разрывы страниц. Параметры `inline`, `nospace`, `headingtheme`, `tabletheme`, `quotetheme`. В HTML-шаблонах значение вставляется без экранирования.
- В справке по шаблонам новые разделы «Диаграммы» и «HTML».

### Изменено

- `html` больше не даёт «недоступно в бесплатной версии Carbone»: шаблоны с ним формируются. В XLSX, PPTX, ODS, ODP `:html` — ошибка шаблона `400` `CARBONE_TEMPLATE` «html не поддерживается в …».
- Диаграммы Word и Excel с тегами в данных, у которых раньше после сборки диапазоны рядов и сохранённые значения не менялись (диаграмма показывала данные шаблона), теперь строятся по данным отчёта. Шаблоны без диаграмм и без `:html` собираются как раньше.

### Исправлено

- Кнопка «Сохранить» в редакторе шаблона не создавала новую версию, если в OnlyOffice был выбран строгий режим совместного редактирования (браузер запоминает этот выбор): правки не доходили до Document Server, и сохранение ждало подтверждения впустую. Теперь редактор всегда открывается в быстром режиме без переключателя.
- «Сохранить» без правок в редакторе больше не ждёт подтверждения впустую: сразу сообщение «Нет несохранённых изменений» (API — `409` `NO_CHANGES`). Статус каждого callback OnlyOffice пишется в журнал API.

### Ограничения

- Диаграммы: не поддерживаются новые типы Office 2016 (дерево, солнечные лучи, гистограмма распределения, ящик с усами и другие), циклы по столбцам, число рядов из данных, многоуровневые подписи категорий, таблицы Excel и именованные диапазоны (не растягиваются), диаграммы, связанные с внешним файлом, диаграммы PPTX и OpenDocument. Графики ECharts (`:chart`) по-прежнему недоступны.
- `:html`: тег — только в тексте абзаца, `:html` — последний форматтер; значение больше 1 МБ, вложенность глубже 32 или больше 4096 незакрытых тегов — ошибка шаблона; в таблице не больше 63 столбцов; с `inline` внутри гиперссылки шаблона ссылки из HTML становятся текстом; в ODT флажки — символы ☒/☐, `tabletheme` не действует. Классы, `<style>` и прочие свойства CSS игнорируются.
- Вид документов в Word и LibreOffice проверен выборочно: в тестах — структурные проверки и конвертация в PDF через OnlyOffice.

## [2.4.0] — 2026-10-11

### Добавлено

- Изображения из данных: тег, который занимает весь замещающий текст картинки-заглушки (`{d.photo}`), заменяет её изображением из data URI (PNG, JPEG, GIF) или по адресу `http(s)://`. `:imageFit(fillWidth|contain|fill)` задаёт, как вписать изображение в рамку заглушки; пустое значение убирает заглушку. Работает в DOCX, XLSX, PPTX, ODT, ODS, ODP, в том числе в циклах (DOCX — картинка «в тексте», ODT — «как символ»). Лимиты — 10 МБ и 100 млн пикселей на изображение, 50 МБ на отчёт.
- Загрузка изображений по адресу — только с хостов из новой настройки `IMAGE_URL_ALLOWLIST` (по умолчанию пусто — выключено), тайм-аут `IMAGE_URL_TIMEOUT_MS` (5000 мс); в Helm — `config.imageUrlAllowlist` и `config.imageUrlTimeoutMs`. Без перенаправлений, не больше 4 загрузок одновременно на отчёт. Если картинку не удалось загрузить (тайм-аут, ответ не 2xx, размер), она убирается, отчёт формируется, в журнал API пишется предупреждение «изображение не загружено». **Доверие определяется только списком:** не вносите в него хосты, которыми управляют авторы данных.
- Штрихкоды и QR-коды: `{d.code:barcode(qrcode)}` в замещающем тексте картинки-заглушки (типы и опции — как в документации Carbone: `ean13`, `code128`, `datamatrix`…, `width`, `height`, `scale`, `includetext`, `rotate`, цвета, `eclevel`).
- Цвета из данных: `:color(p|cell|row|shape|part, text|background|highlight|border)` в DOCX, PPTX, ODT, ODP.
- Ссылки: адрес гиперссылки из данных проверяется (без схемы — `https://`; допустимы `http`, `https`, `mailto`, `tel`), недопустимый заменяется значением `:defaultURL(...)` или `#`.
- В справке по шаблонам новый раздел «Изображения, штрихкоды, цвета, ссылки»; `pnpm help:check` для примеров с картинкой проверяет, что отчёт собран без ошибки и заглушка заменена.

### Изменено

- Ошибка в теге шаблона (сообщение Carbone с ` Source: "{метка}"`, например неверное изображение, хост вне списка, неверный штрихкод, ошибка `drop`) при формировании и предпросмотре теперь `400` с кодом `CARBONE_TEMPLATE` и текстом «ошибка шаблона: …» вместо `502` `CARBONE_ERROR`. Прочие сбои сборки — по-прежнему `502`. Если ваши интеграции различали ошибки по коду `502`, учтите новый код.
- `color`, `barcode`, `defaultURL` больше не дают «недоступно в бесплатной версии Carbone»: шаблоны с ними формируются. `barcode` в обычном тексте (не в картинке) — ошибка шаблона «штрихкод ставится в замещающий текст картинки».
- Адреса динамических ссылок, которые раньше попадали в документ как есть, теперь проверяются: `javascript:`, `data:`, адреса с `localhost`, IP-адресом или именем хоста без домена верхнего уровня (например, внутренний `http://server:8080`), относительные адреса и якоря (`#раздел`, `../файл.pdf`) становятся `#`. Для внутренних ссылок используйте полное имя хоста. Тег в самом начале адреса (`{d.base}/items/{d.id}`) вставляется как есть, как в 2.3.0; значения тегов после статической части кодируются.
- Замещающий текст картинок из шаблонов 2.3.0 работает как раньше: смешанный текст с тегами («Фото {d.name}») печатается, картинка не меняется и не удаляется; тег, который занимает весь замещающий текст, со значением — обычным текстом (не `data:` и не `http(s)://`) тоже печатается, картинка остаётся. Картинку заменяет только значение-изображение, а пустое значение (`null`, `''`) её убирает.

### Ограничения

- Не поддерживаются: `:autoOrient`, SVG-изображения (ошибка «SVG не поддерживается»), штрихкоды шрифтом, `bindColor` (по-прежнему ничего не красит — используйте `:color`), `failOn`, изображения в HTML-выводе.
- `:color` в XLSX и ODS — ошибка шаблона.
- Несколько изображений в цикле рассчитаны на DOCX (картинка «в тексте») и ODT (привязка «как символ»); картинка с абсолютной позицией (XLSX, PPTX, ODS, ODP) при повторе циклом не сдвигается — копии ложатся на место заглушки.
- Ссылки через поле Word `HYPERLINK` и форма EE для XLSX без фигурных скобок (`d.url`) не проверяются. В адресе со статической частью (`https://site.ru/?id={d.id}`) значение тега после статической части кодируется, а сохраняется весь адрес (в Carbone EE — только динамическая часть).
- Изображения и штрихкоды на реальных Word, LibreOffice и OnlyOffice проверены выборочно: в тестах — структурные проверки документа и конвертация в PDF через OnlyOffice.

- Изменение доступа к шаблону (публичность, категория, группы) теперь обновляет время изменения шаблона: по нему загрузка из архива определяет, что шаблон изменился после предпросмотра.

- Шаблон, где в строке-разделителе `[i+1]` стоит метка `[i]` (например, `{d.cars[i].qty}`), а дальше идёт вторая таблица или абзацы по тому же массиву, давал пустой документ без ошибки. Теперь рендер останавливается с ошибкой `The marker … is in the [i+1] row of array "…"`: в строке `[i+1]` оставьте только метки `[i+1]` или пустые ячейки. Carbone EE на таком шаблоне выводит таблицы с повторами.

### Ограничения

- Если во время загрузки шаблонов кто-то вручную создаёт шаблон с тем же именем, возможен дубль имени.

## [2.2.0] — 2026-10-10

### Добавлено

- Агрегаторы Carbone в шаблонах: `aggSum`, `aggAvg`, `aggMin`, `aggMax`, `aggCount`, `aggCountD`, `aggStr`, `aggStrD` (итог по всему набору или по отобранным элементам, подытог по вложенному массиву) и `cumSum`, `cumCount`, `cumCountD` (нарастающий итог по строкам цикла), в том числе с группировкой `aggSum(.поле)`. `:count()` нумерует строки цикла 1, 2, 3… без пропусков при фильтре. Раньше такие шаблоны не формировались («недоступно в бесплатной версии Carbone»). Подытоги по группам собираются в шаблоне через `:set` и `aggSum`. В справке по шаблонам новый раздел «Итоги и нумерация» и пример «Подытоги по группам (:set)», примеры проверены на нашей сборке.
- `drop` и `keep`: удаление абзаца, строки, столбца, таблицы, рисунка, диаграммы, фигуры (в ODS — листа, в ODP — слайда) по условию, например `{d.f:ifEQ(true):drop(p)}`, `{d.cars[i].ok:ifEQ(false):drop(row)}`; `drop(p, 3)` и `drop(row, 3)` убирают несколько подряд. Без условия решает само значение: удаляют `true`, ненулевое число, непустой текст, кроме `"0"` и `"false"`; флаги 0/1 из БД работают как есть (`{d.rows[i].archived:drop(row)}`). Работают в DOCX, ODT, XLSX, ODS, PPTX, ODP; в справке по шаблонам — примеры в разделе «Условия».

### Ограничения

- XLSX: `drop(col)` не пересчитывает объединённые ячейки, автофильтр и условное форматирование; на листе с форматированной таблицей («Форматировать как таблицу») `drop(col)` — ошибка шаблона.
- `cumSum`, `cumCount`, `:count()` и итоги по `[]` считают и строки, удалённые `drop(row)`: чтобы строка не попала ни в нумерацию, ни в итог, отбирайте строки фильтром цикла.
- Итоги с фильтром в скобках (`{d.rows[ok=true].qty:aggSum}`) на десятках тысяч строк считаются секунды: на таких объёмах считайте их в SQL.
- `drop`/`keep` не работают во вложенных файлах (данные диаграмм); `drop(col)` не поддерживается в таблицах с горизонтально объединёнными ячейками.
- Сортировка по убыванию (`[-qty, i]`) в Carbone пока не реализована и в 2.2.0 не добавлена: сортируйте в SQL (`ORDER BY … DESC`).

- Шаблоны с парой `hideBegin`/`hideEnd` на границе строки `[i+1]` больше не дают ошибку (шаблоны, собиравшиеся без ошибки, собираются как раньше).
- `CONVERT_ERROR` при SIGTERM во время конвертации.

## [2.0.0] — 2026-10-09

### Несовместимые изменения

- **Контейнера Carbone больше нет.** Отчёты собирает API встроенной сборкой Carbone Community Edition 3.8.2 (`packages/carbone`, воркеры `worker_threads`). Переменная `CARBONE_URL` не читается, том шаблонов Carbone не нужен, блок `carbone:` в values чарта Helm удалён.
- **OnlyOffice обязателен для любого отчёта:** PDF и перевод в ODT/ODS делает Document Server. Вёрстка PDF может немного отличаться от отчётов 1.x (там конвертировал LibreOffice).
- **`API_SELF_URL`:** Document Server забирает файлы у API по одноразовой ссылке. В compose и Helm значение по умолчанию подходит; в Helm используется IP пода (рассчитано на IPv4), внешний Document Server должен достигать IP подов API.
- Helm: лимит памяти `api.resources` — не менее 2Gi (новое значение по умолчанию; `requests` — 500m / 512Mi).
- Поведение шаблонов, как в Carbone EE: `ifEmpty` не обрывает цепочку форматтеров; аргумент в кавычках, начинающийся с точки (`:formatN('.x')`), — строка, а не путь к данным; ошибка вместо молчаливой сборки у шаблонов с `hideBegin` в конце строки (снято в 2.0.1).

Порядок обновления с 1.x — в README, раздел «Обновление с 1.x»: бэкап, `docker compose up -d --no-build --remove-orphans`, удаление тома `<проект>_carbone_templates`, очистка `CARBONE_URL` и ключей `cr:carbone:tpl:*` в Redis (по желанию). Шаблоны и отчёты в S3 не меняются.

### Добавлено

- Пул воркеров рендера: `RENDER_WORKERS` (по умолчанию `min(4, число ядер)`), `RENDER_TIMEOUT_MS`, предел кучи потока `RENDER_WORKER_MEMORY_MB` (по умолчанию из лимита памяти контейнера; в Helm `config.renderWorkerMemoryMb`).
- Синтаксис бесплатного режима Carbone 5: итератор `.i`, циклы по массивам строк, `:set`, новые форматтеры; отключённые платные функции дают ту же ошибку, что и EE. Платные функции Carbone EE (например, `aggSum`) не поддерживаются.
- Проверка сборки в CI с настоящим Document Server и smoke в kind (рендер PDF и DOCX).

## [1.0.0] — 2026-10-09

Первый выпуск: редактор шаблонов в браузере (OnlyOffice), источники данных и отчёты, вход через LDAP/Active Directory, резервное копирование с восстановлением из админки, хранение файлов на диске или в S3, запуск в Docker Compose и чарт Helm.
