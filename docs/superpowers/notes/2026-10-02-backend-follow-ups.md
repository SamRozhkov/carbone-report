## Для Плана 2 (фронтенд)

- [x] Ошибка `VALIDATION` приходит в двух формах `details`:

- [x] Сохранение шаблона (`POST /api/templates/:id/save`) может вернуть `409 NOT_OPEN`, если документ не открыт в редакторе. Например, файл заменили, пока редактор был открыт.

- Для неизвестного маршрута Fastify отвечает 404 по-английски. Фронтенду эти тексты показывать не нужно.

## Для Плана 3 (Docker, nginx, E2E)

Инфраструктурные пункты ниже выполнены в ветке docker (nginx, образ `api`, Document Server). В E2E остаётся живая проверка.

- nginx:
  - не проксировать `/internal/*`;
  - убедиться, что пути вида `/api/../internal` не нормализуются в проксируемые;
  - на `/onlyoffice/` убрать заголовок `Cookie`, чтобы сессия админа не уходила в Document Server;
  - выставить `proxy_read_timeout` больше, чем `RENDER_TIMEOUT_MS` плюс время выполнения запросов. Дефолтных 60 с меньше, чем 120 с на рендер.
- Образ `api`:
  - `WORKDIR apps/api` или переменная `MIGRATIONS_DIR`;
  - у Document Server `ALLOW_PRIVATE_IP_ADDRESS=true` и общий `JWT_SECRET`.
- В E2E проверить на живых контейнерах (Plan 3: проверено, см. «Итоги E2E» ниже):
  - реальный формат ответов Carbone 5: текст «Template not found», `content-type` скачиваемого файла;
  - поведение OnlyOffice при закрытии документа после forcesave: какой статус придёт, 2 или 4, и сменится ли `doc_key`;
  - повторная загрузка шаблона в Carbone после «Template not found». Обе проверки пока не выполнялись на живых контейнерах и войдут в Playwright E2E Плана 3.
- Для Планов 2 и 3 добавить базовые заголовки безопасности: `server_tokens off`, `X-Content-Type-Options`, `Referrer-Policy`, `frame-ancestors` с разрешением same-origin для OnlyOffice.
- `RENDER_TIMEOUT_MS` ограничивает только Carbone. Каждый SQL-запрос ограничен отдельно (`QUERY_TIMEOUT_MS`), общего дедлайна на запуск нет.

## Отложенные мелочи (не блокируют)

- Сессии не отзываются: смена пароля не завершает уже выданные cookie (TTL 12 ч). Блокировка пользователя действует сразу.
- Ограничение попыток входа и кэш `templateId` Carbone хранятся в памяти процесса. Для одного экземпляра этого достаточно.
- Соединения с источниками по SSL не проверяют сертификат сервера (`rejectUnauthorized: false`).
- `numeric` с высокой дробной точностью теряет дробные знаки при переводе в number. Массивы `int8[]`/`numeric[]` не преобразуются.
- Callback OnlyOffice без `exp` можно переиграть, пока жив текущий `doc_key`. Сеть внутренняя, устаревшие ключи игнорируются.
- Строка шаблона остаётся заблокированной, пока файл скачивается из Document Server (до 60 с).
- Если файл записан, а коммит в БД упал, на диске остаётся изменённый файл. Это касается callback и `PUT /file`.
- Тесты не покрывают несколько мест:
  - лимит страниц `/api/runs` и пагинацию;
  - ответ 410 при отсутствии файла на диске;
  - callback, подписанный чужим секретом, и статус 7;
  - сценарии одновременной работы нескольких пользователей.
- Логгер запросов использует собственный сериализатор (он скрывает `?t=`). Из-за этого в логах нет `hostname` и `remoteAddress`.

## Итоги E2E (План 3)

Набор из 5 тестов зелёный дважды подряд при строгой CSP. Что выяснилось по ходу:

- **Zod JIT и CSP.** Проба zod v4 `new Function('')` нарушала `script-src`. Исправлено в `apps/web/src/zod-config.ts` (`z.config({ jitless: true })`), модуль импортируется первым в `main.tsx`.
- **Сохранение из OnlyOffice не работало.** Callback получал браузерный URL файла. `apps/api/src/modules/onlyoffice/download-url.ts` переписывает его на `ONLYOFFICE_INTERNAL_URL` и пропускает только путь `/cache/files/`.
- **Лимит входа.** Из-за 10 попыток в минуту E2E использует одну сессию админа на весь набор.
- **Ввод в OnlyOffice.** Текст набирается через `page.keyboard.type` после клика по `#id_viewer_overlay`; затем ждём «Все изменения сохранены».
- **`doc_key`.** После закрытия отредактированной сессии ключ сменился в течение 20 с (статус 2). Закрытие без правок (статус 4) не проверялось.
