- [x] Ошибка `VALIDATION` приходит в двух формах `details`:

## Для Плана 3 (Docker, nginx, E2E)

Инфраструктурные пункты ниже выполнены в ветке docker (nginx, образ `api`, Document Server). В E2E остаётся живая проверка.

- nginx:
  - не проксировать `/internal/*`;
  - убедиться, что пути вида `/api/../internal` не нормализуются в проксируемые;
  - на `/onlyoffice/` убрать заголовок `Cookie`, чтобы сессия админа не уходила в Document Server;
  - выставить `proxy_read_timeout` больше, чем `RENDER_TIMEOUT_MS` плюс время выполнения запросов. Дефолтных 60 с меньше, чем 120 с на рендер.
- Образ `api`:
  - `WORKDIR apps/api` или переменная `MIGRATIONS_DIR`;
  - у Document Server `ALLOW_PRIVATE_IP_ADDRESS=true` и общий `JWT_SECRET`.
- Проверить на живых контейнерах:
  - [x] реальный формат ответов Carbone 5: текст «Template not found». Сделано (План 4, Task 7): на живом Carbone ответ `404`, `content-type: application/json; charset=utf-8`, тело `{"success":false,"error":"Template not found","code":"w100"}`. `content-type` скачиваемого файла E2E проверяет косвенно (PDF и DOCX скачиваются и разбираются);
  - [~] поведение OnlyOffice при закрытии документа после forcesave: частично наблюдалось в E2E Плана 3. После закрытия отредактированной сессии `doc_key` сменился; какой статус пришёл в callback, тест не определял. Закрытие без правок не проверялось;
  - [x] повторная загрузка шаблона в Carbone после «Template not found». Сделано (План 4, Task 7): `pnpm stack:smoke -- --carbone-restart` пересоздаёт контейнер `carbone` вместе с томом `carbone_templates` и рендерит снова. API загружает шаблон повторно и пишет в лог «шаблон отсутствует в Carbone, загружаем повторно».
- Для Планов 2 и 3 добавить базовые заголовки безопасности: `server_tokens off`, `X-Content-Type-Options`, `Referrer-Policy`, `frame-ancestors` с разрешением same-origin для OnlyOffice.
- `RENDER_TIMEOUT_MS` ограничивает только Carbone. Каждый SQL-запрос ограничен отдельно (`QUERY_TIMEOUT_MS`), общего дедлайна на запуск нет.

## Отложенные мелочи (не блокируют)

- [x] Сессии не отзываются: смена пароля не завершает уже выданные cookie (TTL 12 ч). Блокировка пользователя действует сразу. Сделано (План 4): `session_version` в пользователе и `sv` в cookie; кнопка «Завершить сессии» у админа (`POST /api/users/:id/sessions/revoke`) и «Выйти везде» (`POST /api/auth/logout-all`). Смена пароля, роли или блокировка тоже завершают сессии.
- Ограничение попыток входа и кэш `templateId` Carbone хранятся в памяти процесса. Для одного экземпляра этого достаточно.
- [x] Соединения с источниками по SSL не проверяют сертификат сервера (`rejectUnauthorized: false`). Сделано (План 4): режимы `disable`/`require`/`verify` и свой CA (PEM) для `verify`.
- `numeric` с высокой дробной точностью теряет дробные знаки при переводе в number. Массивы `int8[]`/`numeric[]` не преобразуются.
- [x] Callback OnlyOffice без `exp` можно переиграть, пока жив текущий `doc_key`. Сеть внутренняя, устаревшие ключи игнорируются. Сделано (План 4): `exp` проверяется с допуском 60 с; без `exp` принимается только `iat` не старше 600 с, так что повтор в этом окне возможен.  `iat` из будущего (дальше допуска 60 с) без `exp` тоже отклоняется. Document Server 9.4 на стенде: `token.outbox.expires` = `5m`, в callback `exp = iat + 300`.
- [x] Строка шаблона остаётся заблокированной, пока файл скачивается из Document Server (до 60 с). Сделано (План 4): файл скачивается до блокировки строки.
- [x] Если файл записан, а коммит в БД упал, на диске остаётся изменённый файл. Это касается callback и `PUT /file`. Сделано (План 4): пути с версией `templates/<id>/v<N>.<ext>`, новая версия пишется в новый файл, старый удаляется после коммита.
- Тесты не покрывают несколько мест:
  - [x] лимит страниц `/api/runs` и пагинацию (План 4, `reports.int.test.ts`);
  - [x] ответ 410 при отсутствии файла на диске (План 4, `reports.int.test.ts`; ранее `cleanup.int.test.ts`);
  - [x] callback, подписанный чужим секретом, и статус 7 (`onlyoffice.int.test.ts`);
  - [ ] сценарии одновременной работы нескольких пользователей. Открыто.

## Итоги E2E (План 3)

Набор из 5 тестов зелёный дважды подряд при строгой CSP. Что выяснилось по ходу:

- **Zod JIT и CSP.** Проба zod v4 `new Function('')` нарушала `script-src`. Исправлено в `apps/web/src/zod-config.ts` (`z.config({ jitless: true })`), модуль импортируется первым в `main.tsx`.
- **Сохранение из OnlyOffice не работало.** Callback получал браузерный URL файла. `apps/api/src/modules/onlyoffice/download-url.ts` переписывает его на `ONLYOFFICE_INTERNAL_URL` и пропускает только путь `/cache/files/`.
- **Лимит входа.** Из-за 10 попыток в минуту E2E использует одну сессию админа на весь набор.
- **Ввод в OnlyOffice.** Текст набирается через `page.keyboard.type` после клика по `#id_viewer_overlay`; затем ждём «Все изменения сохранены».
- **`doc_key`.** После закрытия отредактированной сессии ключ сменился в течение 20 с. Это наблюдение по `editor-config`: статус callback (2 или 4) тест не определял, статус 2 только предполагается. Закрытие без правок не проверялось.
- **Carbone «Template not found».** Не проверялось: ни текст ответа, ни повторная загрузка шаблона. Пункты оставались открытыми; закрыты в Плане 4 (см. «Для Плана 3» выше).

## Итоги Плана 4 (усиление)

Ветка `feat/hardening`, 8 задач. E2E: 6 тестов зелёные дважды подряд при строгой CSP, 0 нарушений. Smoke зелёный.

**Что сделано:**

- **Отзыв сессий.** У пользователя есть `session_version`, cookie несёт `sv`. Смена пароля, роли или блокировка через `PATCH` увеличивает версию. Админ завершает сессии кнопкой «Завершить сессии» (`POST /api/users/:id/sessions/revoke`), пользователь — кнопкой «Выйти везде» (`POST /api/auth/logout-all`). E2E `sessions.spec.ts`: после отзыва следующий переход пользователя ведёт на `/login`.
- **SSL источников.** Режимы `disable`/`require`/`verify`, для `verify` можно указать свой CA (PEM). Миграция переводит `ssl=true` в `require`.
- **Callback OnlyOffice.** Старые токены отклоняются: `exp` проверяется с допуском 60 с, без `exp` принимается только `iat` не старше 600 с и не из будущего (повтор в этом окне возможен). Document Server 9.4 присылает `exp`.
- **Файлы шаблонов с версией.** Пути `templates/<id>/v<N>.<ext>`. Callback скачивает файл вне блокировки строки. Миграция при старте переносит старые файлы (на демо-стенде перенесено 2).
- **Carbone и тесты.** Реальный ответ «Template not found» зафиксирован, повторная загрузка проверена в smoke (`--carbone-restart`). Добавлены тесты пагинации `/api/runs` и ответа 410.

**Решения по ходу:**

- После выката старые cookie без `sv` недействительны: всем нужно войти заново.
- Правка своей учётной записи выдаёт новую cookie, только если `sv` не изменилась с момента проверки сессии. Иначе запрос, начатый до отзыва, получил бы свежую cookie.
- `sslMode` в API обязателен. Иначе клиент старого формата (`{ ssl: true }`) молча переключил бы источник на соединение без шифрования.
- Переключатель SSL в форме — группа (`role="group"`), а не `<label>`: клик по заголовку поля не выбирает «Без SSL».
- Если старую версию файла удалили во время рендера, рендер берёт текущий файл.
- `smoke --carbone-restart` удаляет том `carbone_templates`. Поэтому он работает только с локальным `BASE_URL` (loopback) и ждёт готовности Carbone до 120 с.
