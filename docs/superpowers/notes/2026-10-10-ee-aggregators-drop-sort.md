## 1. Агрегаторы (A)

Бейдж: ENTERPRISE, Cloud / On-premise / Embedded Carbone JS v4.0+ (A). [неуверенно] Два прогона пересказа разошлись: один указал Embedded v4.0+ как доступный, другой написал «недоступно в Embedded». Наша матрица (community-matrix, §4) фиксирует: «v4.0+, без бейджа Enterprise». Нужна ручная сверка бейджа на самой странице.

Определение: агрегатор обрабатывает набор значений и возвращает один результат; используется самостоятельно (вне цикла) или внутри цикла.

| Форматтер | Аргументы | Смысл | Пример (данные из A: 6 машин, qty = 1,4,3,2,1,10) |
|---|---|---|---|
| `aggSum(partitionBy)` | partitionBy необязателен | сумма | `{d.cars[].qty:aggSum}` -> 21; с фильтром `{d.cars[sort>1].qty:aggSum}` -> 19; `{d.cars[sort>1].qty:mul(.sort):aggSum}` допустим (формат. до агрегатора) |
| `aggAvg(partitionBy)` | то же | среднее | 3.5; с фильтром 4.75 |
| `aggMin(partitionBy)` | то же | минимум | 1; с фильтром 2 |
| `aggMax(partitionBy)` | то же | максимум | 10 |
| `aggCount(partitionBy)` | то же | число элементов; значение слева игнорируется | `{d.cars[].qty:aggCount}` -> 6; с фильтром 4 |
| `aggCountD(partitionBy)` | то же | число различных значений | `{d.cars[].brand:aggCountD}` -> 4 |
| `aggStr(separator, partitionBy)` | separator по умолчанию `', '` | конкатенация значений | `Lexus, Faraday, Venturi, Faraday, Aptera, Venturi`; `aggStr(' | ')` — через пайп |
| `aggStrD(separator, partitionBy)` | как aggStr | конкатенация только различных | `Lexus, Faraday, Aptera, Venturi` |
| `cumSum(partitionBy)` | | накопительная сумма по строкам | `{d[i].qty:cumSum}` -> 1, 5, 8, 10, 11, 21 |
| `cumCount(partitionBy)` | значение слева игнорируется | сквозной порядковый номер строки | `{d[i].qty:cumCount}` -> 1..N; `cumCount(.brand)` — нумерация сбрасывается по бренду |
| `cumCountD(partitionBy)` | | накопительный счётчик различных | `{d[i].brand:cumCountD}` -> 1, 2, 3, 3, 4, 4 (исправлено 2026-10-10: в пересказе было 1, 2, 2, 3, 4, 4, что не сходится с данными — третья строка Venturi новая; реализовано по определению, спецификация §31.1) |

### Partition by
- Аналог SQL `PARTITION BY`: независимый расчёт по группам. Синтаксис `{d[i].qty:aggSum(.brand)}` — итог по бренду на каждой строке (Lexus 1, Faraday 6, Venturi 13, ...). Аргумент — путь с ведущей точкой (`.brand`), относительный к текущему элементу (A).
- Для aggStr/aggStrD partitionBy — второй аргумент после separator (A, сигнатуры). [неуверенно] Точный пример `aggStr(', ', .brand)` на странице не подтверждён.

### Где применимы
- Вне цикла: `{d.cars[].qty:aggSum}` — «итого» (A).
- Внутри цикла `[i]`: агрегат рядом с накоплением, например `{d[i].qty:aggSum}` + `{d[i].qty:cumSum}` (A).
- Вложенные массивы: `{d[i].cities[].cars:aggSum}` -> подытог на каждую страну (France 151, Italy 22) (A).
- Комбинация `{d[i].cities[].cars:aggSum:cumSum}` -> подытоги нарастающим итогом (France 151, Italy 173) (A).
- Фильтры в скобках работают до агрегации (`[sort>1]`) (A).
- Форматтеры до агрегатора допустимы (`:mul(.sort):aggSum`). После агрегатора документирован только `:cumSum` [неуверенно про остальные].

### Ограничения
- Нельзя обращаться к значению в под-объекте: `{d[].sub.qty:aggSum}` не работает. Обход: `{d[]:print(.sub.qty):aggSum}` (A).
- `:count` как алиас cumCount: на странице A не найден. Источник утверждения «`:count()` переписывается во внутренний `cumCount`» — только наша матрица (community-matrix, строка 19), т.е. наблюдение за поведением CE, а не документация. Документация `:count` — отдельная страница formatters (не читалась). [неуверенно]
- Обработка null / нечисловых значений: на странице A не описана. [неуверенно] Нужны эксперименты на EE-эталоне (если есть доступ без нарушения clean-room — иначе принимать решение самим: пропускать null).
- Версия: v4.0 (бейдж A). Конкретный минор для aggStrD/cumCountD неизвестен.

## 2. drop / keep (D)

Бейдж: ENTERPRISE, Cloud / On-premise / Embedded v4.0+ (D). [неуверенно] Один прогон написал «не Embedded»; нужна ручная сверка.

Семантика: `:drop(el)` удаляет элемент, если условие истинно; `:keep(el)` оставляет, если условие истинно (иначе удаляет). Условие — предшествующий форматтер `ifXX` или булево значение: `{d[i].name:ifIN('Falcon'):drop(row)}` удаляет строки с «Falcon»; `{d.text:ifEM:drop(p, 3)}`.
Преимущества: один тег вместо Begin/End; элемент удаляется без остаточных пробелов/пустых абзацев.

| Элемент | Что скрывает | Где ставить тег |
|---|---|---|
| `row` | строку таблицы | в ячейке строки |
| `col` | столбец | любая ячейка столбца |
| `p` | абзац | внутри абзаца |
| `img` | картинку | в title/alt-тексте картинки |
| `table` | таблицу целиком | в ячейке таблицы |
| `chart` | диаграмму | в alt-тексте диаграммы |
| `shape` | фигуру | в title/alt-тексте |
| `slide` | слайд | в текстовом блоке слайда (ODP only) |
| `item` | элемент списка | в элементе списка (ODP/ODT) |
| `sheet` | лист | в ячейке (ODS only) |
| `h` | заголовок | в заголовке (ODT) |
| `div`, `span` | HTML-элементы | HTML |

Второй параметр N только для `p` и `row`: `drop(p, 3)` / `drop(row, 3)` — текущий + следующие (пример в D: «текущий и следующие 2», т.е. N считает и текущий элемент).

Поддержка форматов: DOCX, ODT, ODS, ODP, XLSX, PPTX, HTML. Ограничения:
- ODS: только `col`, `row`, `img`, `sheet`.
- XLSX: только `row`, `col`.
- PPTX: `col`, `row`, `img`, `p`, `shape`, `chart`, `table`.
- HTML: `table`, `col`, `row`, `p`, `div`, `span`.
- DOCX/ODT/ODP: полный набор не перечислен явно; из таблицы следует DOCX/ODT: row, col, p, img, table, chart, shape (h, item — ODT; item, slide — ODP). [неуверенно: точная матрица DOCX]
Прочие ограничения: объединённые ячейки не поддерживаются (в планах); один `drop(col)` на столбец; вложенные таблицы в ячейках той же строки не затрагиваются.

## 3. Сортировка в циклах (S)

Бейдж: COMMUNITY FEATURE, v2.0+ (S). Т.е. по документации — бесплатная.

- По возрастанию: `{d.cars[power, i].brand}` (повтор-строка: `{d.cars[power+1, i+1].brand}`). Сортирует по `power`, при равенстве — по позиции `i`.
- Несколько ключей: `{d.cars[power, sub.size, i].brand}`; вложенные свойства через точку.
- Результат примера 1: Peugeot, Lexus, BMW, Ferrari; примера 2: Kia, Aptera, Peugeot, BMW, Ferrari.
- По убыванию: «Coming soon in Carbone v5» (S, на 2026-10-06 всё ещё «скоро»). Синтаксис не определён -> в документации ни `[-sort]`, ни `desc` не заявлены. Реализовывать убывание можно только как наше расширение; [неуверенно] о будущем синтаксисе Carbone.

## 5. Что делает текущая реализация (локально)

- `apps/web/src/pages/admin/help/content.ts` (строки ~390, 528-560): раздел «Недоступно в бесплатной версии» — все агрегаторы (`aggSum, aggAvg, aggMin, aggMax, aggCount, aggCountD, aggStr, aggStrD, cumSum, cumCount, cumCountD`, `:count()`) отключены, шаблон не формируется; рекомендация — считать итоги в SQL, количество — `{d.cars:len()}`. `drop()`/`keep()` отключены; вместо них `hideBegin/hideEnd` для абзацев и фильтр цикла для строк. Есть пример `na-sort-desc` (~строка 629).
- `docs/superpowers/notes/2026-10-13-carbone-community-matrix.md`: агрегаторы -> ошибка `Formatter "aggSum" is disabled in the Community Edition` (также с фильтром, вложенностью, `mul(.price):aggSum`, partition); `:count()` отключён, т.к. переписывается в `cumCount`; `drop/keep` -> `Formatter "drop" is disabled in the Community Edition`; `hideBegin/hideEnd` внутри строк таблицы портят таблицу; сортировка asc `[qty, i]` и multi-sort работают; `[-qty, i]` молча игнорируется (порядок исходный); `:set` работает, но суммирование через него считает первый элемент дважды.

## 6. Крупнейшие неопределённости
1. Бейдж Embedded v4.0+ для агрегаторов/drop противоречив между прогонами пересказа; нужна ручная сверка страниц.
2. Поведение null/нечисловых значений и пустых наборов у агрегаторов нигде не документировано.
3. `:count` как алиас cumCount подтверждён только наблюдением на CE, не документацией.
4. Синтаксис убывающей сортировки v5 не опубликован (только «скоро»).
5. Точная матрица элементов drop/keep для DOCX/ODT/ODP и семантика N (включает ли текущий) выведены из кратких примеров; changelog (версии релизов) недоступен (404).
