# 2.3.0: перенос шаблонов между средами — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Администратор выгружает один или несколько шаблонов (файл, запросы, параметры, категория, группы, публичность, формат) в архив и загружает его в другой среде с сопоставлением источника данных и выбором действия при совпадении имени.

**Architecture:** Формат архива описан схемой zod в `packages/shared` (общая для API и web). API: сервис экспорта (сборка `manifest.json` + файлы из хранилища в zip через `jszip`, уже зависимость API), сервис импорта (разбор и проверка архива → план → применение в одной транзакции с откатом файлов в хранилище). Web: кнопки выгрузки в списке и карточке, окно загрузки с предпросмотром.

**Tech Stack:** Node 22, Fastify 5, drizzle, zod 4, jszip, React 19 + Gravity UI, react-query, vitest, testcontainers (интеграционные тесты API).

**Spec:** `docs/superpowers/specs/2026-10-02-carbone-reports-design.md`, §33.

## Global Constraints

- Ветка `feat/2.3.0`. Слияние и тег — только контроллер, с разрешения владельца.
- Node 22: `export PATH=$HOME/.nvm/versions/node/v22.17.0/bin:$PATH`.
- Пароли источников, CA, `.env`, секреты не попадают в архив, журналы и ответы.
- Тексты для пользователя, журналы и комментарии — на русском, в стиле окружающего кода. Ошибки API — `AppError` с кодами, как в соседних модулях.
- Маршруты импорта/экспорта — только администраторы (те же guard, что у `POST /api/templates/upload`).
- Каждый коммит заканчивается `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Перед коммитом: `pnpm exec prettier --check .`, `pnpm lint`, `pnpm typecheck`, модульные тесты затронутых пакетов.
- Интеграционные тесты API (Docker, testcontainers) можно запускать локально только для своих новых файлов: `cd apps/api && pnpm exec vitest run --config vitest.int.config.ts test/<файл>`; стек docker compose не трогать.

## Review Focus

1. Архив-бомба, `../` в путях, лишние файлы, подменённый файл шаблона (sha256) — 400 `IMPORT_INVALID`, без записи в хранилище и БД. Тест: Task 2.
2. Сбой посреди импорта нескольких шаблонов (например, второй шаблон нарушает уникальность) — в БД нет ни одного нового/изменённого шаблона, загруженные файлы удалены из хранилища. Тест: Task 2 (интеграционный).
3. `update` существующего шаблона, открытого в OnlyOffice, — новый `docKey`, версия +1, история запусков на месте. Тест: Task 2.
4. Круговой перенос: экспорт → импорт `create` в «другую среду» (другой источник с тем же именем) → экспорт снова → `manifest.json` совпадает с первым по содержимому (кроме `exportedAt`, `appVersion`). Тест: Task 2 (интеграционный).
5. Нет источника с таким именем и администратор не выбрал источник — кнопка «Загрузить» неактивна, API без `datasourceId` — 400. Тест: Task 3 и Task 2.
