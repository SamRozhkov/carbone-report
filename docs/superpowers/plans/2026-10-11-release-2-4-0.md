# 2.4.0: изображения из данных, штрихкоды, цвета, ссылки — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Встроенная сборка Carbone (`packages/carbone`) заменяет картинки-заглушки изображениями и штрихкодами из данных, красит абзацы/ячейки/строки/фигуры через `:color`, проверяет адреса динамических ссылок и поддерживает `:defaultURL`; API передаёт настройки загрузки изображений по URL и отдаёт ошибки шаблона как 400.

**Architecture:** Три новых модуля в `packages/carbone/lib` по образцу `drop.js` (2.2.0): подготовка меток → форматтер печатает жетон с nonce → разбор XML после сборки. Изображения и штрихкоды затрагивают несколько файлов архива (rels, media, `[Content_Types].xml`, `META-INF/manifest.xml`), поэтому их заменяет асинхронный шаг уровня отчёта в `renderBuffer` (`lib/index.js`, между `walkFiles` и `finishXlsx`); цвета и ссылки обрабатываются пофайлово в `buildXML`, как `drop.apply`. Общий разбор XML (`parse`, `closest`, `attr`, `setAttr`, `family`…) выносится из `drop.js` в `lib/xmltree.js`.

**Tech Stack:** Node 22, CommonJS (`packages/carbone`), mocha; `bwip-js` (MIT) и `image-size` (MIT) — точные версии через `=`; API: Fastify 5, zod 4, worker_threads, vitest; Helm, docker compose.

**Spec:** `docs/superpowers/specs/2026-10-02-carbone-reports-design.md`, §32 (поведение EE — `docs/superpowers/notes/2026-10-10-ee-images-barcodes-colors.md`).

## Global Constraints

- Ветка `feat/2.4.0` от `main` (5b3bdea, 2.3.0). Слияние и тег `v2.4.0` — только контроллер, с разрешения владельца.
- Node 22: `export PATH=$HOME/.nvm/versions/node/v22.17.0/bin:$PATH`.
- Clean-room: код образа carbone-ee не читать и не запускать для изучения кода; источник — только публичная документация (справочник выше) и §32.
- Новые зависимости `packages/carbone`: только `bwip-js =4.11.4` и `image-size =2.0.4` (pure JS, MIT), версии через `=`; упомянуть в `packages/carbone/NOTICE.md`.
- Форматы изображений: PNG, JPEG, GIF. SVG — ошибка «SVG не поддерживается». Лимиты: одно изображение до 10 МБ после декодирования; все изображения отчёта до 50 МБ (превышение — ошибка отчёта).
- Загрузка по URL: по умолчанию выключена; `IMAGE_URL_ALLOWLIST` (хосты через запятую, точное совпадение, порт — часть хоста, только если указан); только `http:`/`https:`; без перенаправлений; `IMAGE_URL_TIMEOUT_MS` по умолчанию 5000; не более 4 одновременных загрузок на отчёт; сбой сети/не 2xx/3xx/размер — заглушка удаляется + предупреждение в журнал API (адрес без query-строки).
- Пустое значение (`null`, `undefined`, `''`) изображения или штрихкода — заглушка удаляется.
- `:color` — цвет 6 hex-цифр с `#` или без, иначе `#888888`; XLSX/ODS — ошибка «color не поддерживается в XLSX/ODS».
- Ссылки: схемы `http`, `https`, `mailto`, `tel`; без схемы — `https://`; недопустимое — значение `:defaultURL(...)`, без него — `#`.
- Не входит: `:autoOrient`, SVG, штрихкоды шрифтом, `bindColor`, `failOn`, изображения в HTML-выводе (`autoOrient` остаётся в `DISABLED`).
- Сообщения ошибок шаблона — на русском, с суффиксом ` Source: "{метка}"` (функция `templateError` как в `drop.js`). Комментарии — на русском, в стиле окружающего кода.

## Решения контроллера (там, где спецификация молчит)

- R1. Ошибки шаблона: сообщения Carbone с ` Source: "` (ошибки меток — builder, drop, новые модули) API отдаёт как `AppError('CARBONE_TEMPLATE', 400, 'ошибка шаблона: ' + текст)`; прочие ошибки Carbone остаются `CARBONE_ERROR` 502. §32.1 требует 400 «как прочие ошибки шаблона»; сейчас они 502.
- R2. Метка становится «меткой изображения», только если она стоит в замещающем тексте картинки-заглушки (DOCX `wp:docPr`/`pic:cNvPr` `descr|title`, VML `alt`; PPTX `p:cNvPr`; XLSX `xdr:cNvPr`; ODF `svg:title`/`svg:desc` внутри `draw:frame` с `draw:image`). Предобработка дописывает таким меткам последний форматтер `:__img`. Тот же текст в обычном абзаце печатается как раньше.
- R3. Метка изображения — только метка, которая занимает весь замещающий текст (без учёта пробелов), или метка с `:barcode`/`:imageFit`; смешанный текст («Фото {d.name}») печатается как в 2.3.0. Значение метки изображения: `data:` или `http(s)://` — изображение (неверный `data:` — ошибка шаблона); null, undefined, '' — заглушка удаляется; иной обычный текст печатается в замещающем тексте, как в 2.3.0, картинка остаётся, без ошибки (изменено по итоговому ревью).
- R4. Смешанный адрес ссылки (статическая часть + метка, `https://site/?id={d.id}`): значение метки после статической части кодируется `encodeURIComponent`; метка в самом начале адреса (`{d.base}/items/{d.id}`) вставляется как есть; проверяется итоговый адрес целиком. В EE сохраняется только динамическая часть — осознанное отличие, записать в NOTICE (изменено по итоговому ревью).
- R5. ODT/ODP `:color`: стиль элемента клонируется в новый автоматический стиль `CRc<n>` (родитель — исходный стиль) с нужным свойством; требование EE «на элементе уже должен быть нестандартный стиль» не действует.
- R6. Предупреждения рендера (сбой загрузки изображения) собираются в `options.warnings: string[]`; `renderBuffer` их не возвращает в Buffer, поэтому добавляется `renderBufferWithWarnings(...)` → `{ buffer, warnings }`; воркер API пересылает `warnings`, рендерер пишет `log.warn`.

## Review Focus

1. Одна картинка в цикле DOCX (`{d.items[i].img}` в `descr`, строка таблицы `[i]`/`[i+1]`): N разных изображений — N отдельных media-файлов и связей, без общих `r:embed`; одинаковые значения могут делить один файл. Тест: Task 2.
2. Значение из данных с `"`, `<`, `&` в замещающем тексте или в адресе ссылки не ломает XML документа (документ открывается, `docxText` читается). Тест: Task 2 и Task 6.
3. Хост вне белого списка, `javascript:` в ссылке, перенаправление 302, ответ 404, тайм-аут, изображение 11 МБ — поведение строго по §32 (ошибка шаблона / удаление заглушки + предупреждение / `#`). Тест: Task 3 и Task 6 (локальный http-сервер в тесте).
4. Шаблон 2.3.0 без новых функций (все golden-эталоны, кроме переведённых в `deviation`) собирается байт-в-байт как раньше: новые шаги не трогают файлы без жетонов. Тест: Task 1 (рендер шаблона без жетонов — `document.xml` и rels идентичны выводу до изменения).
5. API: ошибка метки нового форматтера приходит клиенту 400 `CARBONE_TEMPLATE` с текстом, а падение воркера — по-прежнему 502. Тест: Task 3.
