# 2.5.0: нативные диаграммы DOCX/XLSX и `:html` — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Встроенная сборка Carbone (`packages/carbone`) правильно заполняет нативные диаграммы Word и Excel данными цикла (диапазоны, кэш точек, числа) и вставляет HTML из данных в DOCX и ODT по `:html` со всеми тегами и параметрами из документации Carbone.

**Architecture:** Диаграммы — новый синхронный шаг уровня отчёта `charts.finish(report)` в `renderBuffer` (`lib/index.js`, после `walkFiles`, до `media.finish`/`finishXlsx`): препроцессор помечает строки и ячейки листов книг с диаграммами исходным номером строки и буквой столбца (служебные атрибуты), после сборки по ним строится отображение строк шаблона в строки результата, переписываются `c:f`, перестраиваются кэши, ячейки числовых рядов становятся числами, служебные атрибуты снимаются. `:html` — по образцу `media.js` (2.4.0): `html.prepare` нумерует метки, форматтер `html` кладёт значение в реестр рендера и печатает жетон, асинхронный шаг `html.finish(report, options)` (до `charts.finish`) разбирает HTML в независимую от формата модель (`lib/html-model.js`, `htmlparser2`) и пишет её в DOCX (`lib/html-docx.js`) или ODT (`lib/html-odt.js`), изображения грузит через `media.loadImage`.

**Tech Stack:** Node 22, CommonJS (`packages/carbone`), mocha; `htmlparser2 =10.1.0` (MIT; зависимости `entities`, `domhandler`, `domutils`, `domelementtype` — BSD-2-Clause); API: Fastify 5, vitest; OnlyOffice Document Server в интеграционном тесте.

**Spec:** `docs/superpowers/specs/2026-10-02-carbone-reports-design.md`, §34 (и §32.1–32.2, §32.5 — изображения и ссылки, на которые ссылается §34.4).

## Решения контроллера (там, где спецификация молчит)

- R1. Отображение строк: препроцессор (только для книг, у которых есть диаграммы: верхний уровень XLSX с `xl/charts/*.xml`, встроенные книги DOCX с `word/charts/*.xml`) дописывает `<row … crRow="<исходный r>">` и `<c … crCol="<буква столбца>">` до `removeRowCounterInWorksheet`. После сборки строки нумеруются подряд (как `addRowCounterInWorksheet`), ячейкам ставится `r = crCol + номер строки` — так пропущенные ячейки шаблона (например, пустая `A1` встроенного листа Word) не сдвигают столбцы. В строке, где `crCol` повторяется (цикл по столбцам), ячейкам `r` не ставится (поведение 2.4.0). Служебные атрибуты снимаются у всех строк и ячеек.
- R2. Диапазон `c:f` строки `s..e`: начало — первая строка результата с `crRow = s`, если её нет — первая строка результата с ближайшим большим `crRow`; конец — последняя строка результата с `crRow = e`, если её нет — последняя с ближайшим меньшим. Если начало > конца (пустой цикл) — диапазон из одной строки `конец + 1`, кэш без точек, `ptCount` 0. Буквы столбцов не меняются.
- R3. `c:multiLvlStrRef` (многоуровневые подписи) не трогается целиком — ни `c:f`, ни кэш (§34.2 «не поддерживается»).
- R4. `{d.x:defaultURL('…'):html}`: `html.prepare` заменяет `defaultURL(арг)` в цепочке метки с `:html` на служебный `__htmlUrl(арг, k)`, который передаёт адрес форматтеру `html` (как `imageFit` → `__img` в `media.js`) и возвращает значение без изменений; адрес — запасной для недопустимых ссылок `a href` внутри HTML.
- R5. Изображение в `:html`: неверный data URI, неподдержанный тип, SVG, хост вне списка, загрузка выключена, сбой сети — картинка пропускается, предупреждение в `options.warnings`; превышение лимитов (10 МБ, 100 млн пикселей, 50 МБ на отчёт) — ошибка шаблона, как §32.1. Для различения `media.js` помечает ошибки лимитов `err.limit = true`; счётчик байтов отчёта переезжает в реестр `options.__media.total` и общий для `media.finish` и `html.finish`.
- R6. Жетон `:html` вне текста абзаца (замещающий текст, атрибут, имя отчёта) — ошибка шаблона `html ставится в текст абзаца.`
- R7. Абзац с меткой, в `w:pPr` которого есть `w:sectPr`: `w:sectPr` остаётся только в последнем созданном абзаце. Копии `w:pPr` для блоков HTML берут `w:jc`, `w:bidi`, `w:ind`, `w:spacing` метки; `w:pStyle` и `w:numPr` метки не копируются в заголовки, пункты списков и таблицы.
- R8. ODT: оформление метки (стиль абзаца, стиль `text:span` вокруг метки) сохраняется внешним `text:span`; HTML-оформление — внутренним `text:span` с автоматическим стилем `CRh<n>` (`style:family="text"`), из которого исключены свойства, уже заданные стилем метки (§34.3 «приоритет у метки»). Автоматические стили — в `office:automatic-styles` того же файла (`content.xml` или `styles.xml` для колонтитулов).

## Review Focus

1. Диаграмма DOCX, сделанная в Word на русском: лист `Лист1`, пустая `A1` без элемента `<c>`, имя ряда в `B1`, метки в строках 2–3 — после рендера имя ряда «Сумма» на месте, N точек с `idx` 0…N−1, `c:f` до строки N+1, встроенная книга открывается (ячейки с правильными `r`). Тест: Task 2.

3. `:html` в ячейке таблицы внутри цикла (`{d.rows[i].note:html}`, 3 строки, у каждой свой HTML со списком и таблицей) — каждая ячейка заканчивается `w:p`, нумерация списков не сквозная между ячейками (свой `w:num` на каждый список), документ открывается. Тест: Task 5–6.
