# 2.10.1: остаточные риски входа и подписи — план

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** закрыть низкие риски 2.10.0 (повтор `jti`, раскрытие логина в callback, пробелы в логине, префиксы cookie, `logUrl`) и отложенные замечания 2.9.1 (схема `meta`, срок загрузки, часы окна, тест через пул).

**Architecture:** точечные изменения в `apps/api` (модули auth и signature, `app.ts`), без миграций и без изменений web. Каждая задача — свой набор тестов и коммит.

**Tech Stack:** Fastify 5, drizzle-orm (Postgres), ioredis, zod, vitest, testcontainers.

**Spec:** `docs/superpowers/specs/2026-10-02-carbone-reports-design.md`, §41 (и §39.8, §40 для контекста).

- Интеграционные: `pnpm --filter @carbone-reports/api exec vitest run --config vitest.int.config.ts <файлы>` (Docker testcontainers). Не запускать два набора тестов одновременно. Никогда не запускать `render-onlyoffice.int.test.ts`.

- Комментарии, сообщения ошибок и журнала — по-русски, в стиле окружающего кода. Токены, пароли, коды авторизации, ключи — никогда в журнал.
- Каждый коммит: сообщение в стиле репозитория (`fix(auth): …`) и отдельный `-m "Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>"`.
- Ветка `feat/2.10.1`; не переключать ветки, не пушить, не мержить.
- Новых миграций нет; схема БД не меняется.

## Review Focus

- Повтор logout token при недоступном Redis-ключе (ошибка Redis) — не должен давать 500 без журнала; поведение: ошибка Redis — как сбой провайдера, `503` (Keycloak повторит).
- `COOKIE_SECURE=true`: выход (`/api/auth/logout`, `/logout-all`, OIDC logout) удаляет и новую, и старую cookie; иначе старая `session` висит в браузере.
- `logUrl` с `%2F`/`%` без пары — не бросает исключение в сериализаторе журнала (иначе падает логирование запроса).
- `trim()` в `LoginBody`: логин из одних пробелов — `400` проверки, а не `401`.
- Окно по `now()` базы: ранняя проверка вне транзакции и решающая под блокировкой обе используют часы базы.

### Task 2: префиксы cookie при `COOKIE_SECURE=true`

**Files:**
- Modify: `apps/api/src/modules/auth/session.ts` (имя cookie от конфигурации)
- Modify: `apps/api/src/modules/auth/routes.ts`, `guards.ts`, `oidc-routes.ts` (все использования `SESSION_COOKIE` и `FLOW_COOKIE`)
- Modify: тесты, импортирующие `SESSION_COOKIE` (`apps/api/test/*.ts`, `helpers.ts`)
- Modify: `docs/operations/keycloak.md` (имена cookie, если упоминаются)
- Test: `apps/api/test/auth.int.test.ts`, `apps/api/test/oidc.int.test.ts`

**Interfaces:**
- Produces в `session.ts`:
  ```ts
  export const LEGACY_SESSION_COOKIE = 'session';
  /** `__Host-`: браузер принимает её только с Secure, Path=/ и без Domain — не подставить с поддомена. */
  export const sessionCookieName = (secure: boolean) => (secure ? '__Host-session' : LEGACY_SESSION_COOKIE);
  ```
  `SESSION_COOKIE` удалить (или оставить только как `LEGACY_SESSION_COOKIE`), чтобы не осталось мест со старым именем. В `oidc-routes.ts`: `const flowCookieName = deps.config.cookieSecure ? '__Secure-oidc_flow' : 'oidc_flow'`.

- [ ] **Step 1: тесты (падают)** — в `auth.int.test.ts` приложение с `cookieSecure: true` (второй аргумент `createTestApp(overrides, config)` — `{ cookieSecure: true }`): вход → `Set-Cookie` начинается с `__Host-session=`, содержит `Secure` и `Path=/`, без `Domain`; `/api/auth/me` с этой cookie — `200`; с той же подписью под именем `session` — `401`; `/api/auth/logout` — `Set-Cookie` очищает и `__Host-session`, и `session`. С `cookieSecure: false` — прежнее имя `session` (существующие тесты). В `oidc.int.test.ts` — при `cookieSecure: true` cookie потока `__Secure-oidc_flow` и callback её читает.
- [ ] **Step 2: реализация** — заменить все чтения/установки/удаления на `sessionCookieName(deps.config.cookieSecure)`; при выходе (`/logout`, `/logout-all`, OIDC logout) дополнительно `clearCookie(LEGACY_SESSION_COOKIE, { path: '/' })`, если имя отличается. Хелперы тестов — брать имя из `sessionCookieName(false)` или искать cookie по имени из приложения.
- [ ] **Step 3: тесты зелёные** — модульные API; интеграционные `auth.int`, `oidc.int`, `users.int`, `ldap-login.int`, `ldap-server.int`, и все прочие файлы, где встречалось `SESSION_COOKIE` (`grep -rl SESSION_COOKIE apps/api`).
