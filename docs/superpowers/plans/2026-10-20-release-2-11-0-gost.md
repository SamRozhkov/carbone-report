# 2.11.0: подпись по ГОСТ через КриптоПро ЭЦП Browser plug-in — план

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** пользователь подписывает отчёт по ГОСТ своим ключом в КриптоПро ЭЦП Browser plug-in; сервер ставит штамп, считает хеш Стрибог, полностью проверяет присланную открепленную подпись CAdES и отдаёт PDF со штампом и `.sig`.

**Architecture:** своя реализация ГОСТ Р 34.11-2012 (Стрибог) и проверки ГОСТ Р 34.10-2012 на TypeScript в `apps/api/src/modules/pdf/sign/gost/`; разбор CMS — `pkijs`. Тяжёлая работа — две новые задачи пула рендера (`gost-prepare`: штамп + хеш; `gost-verify`: проверка CAdES). Два маршрута (`prepare`/`complete`) с таблицей ожиданий; браузер подписывает только хеш (`SignHash`), PDF в браузер не передаётся.

**Tech Stack:** Fastify 5, drizzle-orm/Postgres, pdf-lib, pkijs/asn1js, `BigInt`; React 19 + Gravity UI + react-query; OpenSSL с движком `gost` (Docker `rnix/openssl-gost`) — только для генерации тестовых данных.

**Spec:** `docs/superpowers/specs/2026-10-02-carbone-reports-design.md`, §42 (контекст — §39.2–39.5, §39.8).

## Решения контроллера (до исполнения)

- **Способ подписи запуска хранится в `report_runs.sign_method`** (`text`, `null` — подпись не разрешена), заполняется при формировании из снимка (`pdf.options.signature?.method ?? 'p12'`, рядом с `signature_position`, `apps/api/src/modules/reports/routes.ts:~129`). Миграция 0014 заполняет `'p12'` у существующих запусков с `signature_position is not null`. Так `GET /api/runs` и маршруты подписи не читают `pdf-options.json`. §42 говорит «из снимка» — колонка и есть копия снимка.
- **`cadesplugin_api.js` не распространяется** (скачивается с сайта КриптоПро после принятия условий; условия распространения не подтверждены). nginx отдаёт его из монтируемого каталога: `location = /cadesplugin_api.js` → `root /usr/share/nginx/cades; try_files /cadesplugin_api.js =404;` (404, а не `index.html`). compose: том `./cades:/usr/share/nginx/cades:ro`; Helm: необязательный ConfigMap `web.cadesPluginConfigMap`. Без файла диалог показывает «Не найден КриптоПро ЭЦП Browser plug-in…» и ссылку на инструкцию.
- **Порядок байтов хеша.** `streebog()` возвращает байты в порядке, в котором хеш лежит в `messageDigest` CMS у OpenSSL (`openssl dgst -md_gost12_256` печатает тот же порядок); `prepare` отдаёт `hash` hex в этом же порядке. Эталоны RFC 6986 записаны как числа — тест сравнивает с перевёрнутым порядком байтов, это нормально.
- **Ошибки проверки CAdES из потока** передаются через существующее поле `field` ответа пула: `field: 'gost'`, `message` — текст отказа §42.4.
