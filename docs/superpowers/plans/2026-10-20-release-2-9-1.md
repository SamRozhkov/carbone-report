# 2.9.1: доработки подписи — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** разбор `.p12` уходит из главного потока API в пул рендера, вторая одновременная подпись пользователя сразу получает `409 SIGN_BUSY`, счётчик неверных паролей переезжает из Redis в Postgres.

**Architecture:** пул рендера получает вид задачи `p12` и умеет возвращать поле ошибки (`field`) и JSON-метаданные (`meta`); зависимость `AppDeps.p12Read` (пул в проде, этот поток в тестах) заменяет прямые вызовы `readP12` в маршрутах. `runFileGate` получает режим `ifBusy` на `pg_try_advisory_xact_lock`. Неверные пароли считает таблица `sign_password_failures` под той же блокировкой пользователя; транзакция при неверном пароле не падает, а возвращает результат, чтобы запись счётчика зафиксировалась.

**Tech Stack:** Node 22, Fastify 5, drizzle-orm 0.45 + drizzle-kit, `node:worker_threads`, node-forge, vitest, React + @tanstack/react-query (web).

**Spec:** `docs/superpowers/specs/2026-10-02-carbone-reports-design.md` §39.8 (и §39.1, §39.3 для контекста).

## Global Constraints

- Node: `export PATH=$HOME/.nvm/versions/node/v22.17.0/bin:$PATH` перед любыми `pnpm`.
- Тексты ошибок дословно: `409 SIGN_BUSY` «другая подпись уже выполняется — повторите через несколько секунд»; `429 TOO_MANY_ATTEMPTS` «слишком много неверных паролей — попробуйте через 15 минут»; `400` «неверный пароль к ключу» (у `/password`); срок — `504 TIMEOUT` «превышено время ожидания».
- Лимит неверных паролей: 5 за фиксированное окно 15 минут от первой неверной попытки; верный пароль счётчик не сбрасывает.
- Пароль и ключ не попадают в логи, ответы, тексты ошибок — ни в главном потоке, ни в потоке пула.
- Лимит загрузок сертификата (10 в минуту, `createRateLimit`, `cr:rl-cert:`) не трогать.
- Сборка форматов (§24.2) по-прежнему ждёт блокировку — режим `ifBusy` только у подписи.
- Комментарии и тексты — по-русски, в стиле окружающего кода. Коммиты заканчиваются второй `-m` строкой `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Не запускать два набора тестов пакетов одновременно; не запускать OnlyOffice testcontainers локально (`render-onlyoffice.int.test.ts`). Интеграционные тесты API (`pnpm --filter @carbone-reports/api exec vitest run --config vitest.int.config.ts <файл>`) используют Docker Postgres — запускать только нужные файлы.
- Не пушить `main`, не мержить, не ставить теги. Пушить `feat/2.9.1` можно.

## Review Focus

1. Неверный пароль внутри транзакции: запись счётчика должна пережить ответ `400` (транзакция фиксируется, а не откатывается) — Task 2, тест «пять неверных → строка count = 5».
2. Занятая блокировка не должна держать соединение `runFilePool`: после `SIGN_BUSY` пул свободен — Task 2, тест `run-file-gate` с `pool.idleCount`/`totalCount`.
3. Ключ из потока: `KeyObject` в главном потоке должен подписывать так же, как ключ из синхронного `readP12`, а буфер DER — быть затёрт — Task 1, тест подписи и проверки `crypto.verify`.
4. `P12Error` через поток: неверный пароль даёт поле `password`, «слишком много итераций» — поле `file`; прочие ошибки потока — не `P12Error` — Task 1.
5. Окно счётчика: строка с `window_start` 16 минут назад и `count = 5` — не блокирует, следующая ошибка начинает окно заново (`count = 1`) — Task 2.

```ts
import { createPrivateKey } from 'node:crypto';
import type { CertificateInfo } from '@carbone-reports/shared';
import type { P12Reader } from '../../../deps';
import { AppError } from '../../../lib/errors';
import { RenderTimeoutError, TemplateRenderError, type RenderPool } from '../../render/pool';
import { P12Error, readP12, type DigestAlg } from './p12';

interface P12Meta {
  cert: string;
  chain: string[];
  info: CertificateInfo;
  digestAlg: DigestAlg;
}

/** Разбор — задачей пула рендера: KDF (до 300 000 итераций) не блокирует главный поток (§39.8). */
export function createPoolP12Reader(pool: Pick<RenderPool, 'run'>): P12Reader {
  return async (file, password, now, deadlineAt) => {
    let r;
    try {
      r = await pool.run(
        {
          kind: 'p12',
          template: file,
          ext: 'p12',
          data: { password, now: now.toISOString() },
          options: { lang: '', timezone: '' },
        },
        deadlineAt,
      );
    } catch (e) {
      if (e instanceof RenderTimeoutError)
        throw new AppError('TIMEOUT', 504, 'превышено время ожидания');
      if (e instanceof TemplateRenderError && (e.field === 'file' || e.field === 'password'))
        throw new P12Error(e.field, e.message);
      // Прочее — внутренняя ошибка; текст потока пользователю не нужен.
      throw new Error('разбор .p12 в пуле рендера не удался', { cause: e });
    }
    const meta = r.meta as P12Meta;
    try {
      return {
        key: createPrivateKey({ key: r.out, format: 'der', type: 'pkcs8' }),
        cert: Buffer.from(meta.cert, 'base64'),
        chain: meta.chain.map((c) => Buffer.from(c, 'base64')),
        info: meta.info,
        digestAlg: meta.digestAlg,
      };
    } finally {
      r.out.fill(0);
    }
  };
}

/** В этом потоке — для тестов API (createTestApp). */
export const inProcessP12Reader: P12Reader = async (file, password, now) =>
  readP12(file, password, now);
```

```ts
import { eq, sql } from 'drizzle-orm';
import type { Db } from '../../db/client';
import { signPasswordFailures } from '../../db/schema';
import type { RunFileTx } from '../../lib/run-file-gate';

export const SIGN_FAILURE_LIMIT = 5;
export const SIGN_FAILURE_WINDOW_MS = 15 * 60_000;

/** Подпись запрещена, пока неверных не меньше пяти и окно (15 минут от первой ошибки) не закончилось. */
export function isSignBlocked(
  row: { count: number; windowStart: Date } | undefined,
  now: Date,
): boolean {
  return (
    !!row &&
    row.count >= SIGN_FAILURE_LIMIT &&
    row.windowStart.getTime() + SIGN_FAILURE_WINDOW_MS > now.getTime()
  );
}

export async function signBlocked(db: Db | RunFileTx, userId: string, now: Date): Promise<boolean> {
  const [row] = await db
    .select({ count: signPasswordFailures.count, windowStart: signPasswordFailures.windowStart })
    .from(signPasswordFailures)
    .where(eq(signPasswordFailures.userId, userId));
  return isSignBlocked(row, now);
}

/** Неверный пароль: окно закончилось или его нет — новое окно с count = 1, иначе count + 1. */
export async function recordSignFailure(tx: RunFileTx, userId: string, now: Date): Promise<void> {
  const expired = sql`${signPasswordFailures.windowStart} + make_interval(secs => ${
    SIGN_FAILURE_WINDOW_MS / 1000
  }) <= ${now}`;
  await tx
    .insert(signPasswordFailures)
    .values({ userId, count: 1, windowStart: now })
    .onConflictDoUpdate({
      target: signPasswordFailures.userId,
      set: {
        count: sql`case when ${expired} then 1 else ${signPasswordFailures.count} + 1 end`,
        windowStart: sql`case when ${expired} then ${now} else ${signPasswordFailures.windowStart} end`,
      },
    });
}
```

В `on conflict do update` ссылка `${signPasswordFailures.windowStart}` — на существующую строку (drizzle выводит `"sign_password_failures"."window_start"`), это и нужно. `${now}` — параметр `timestamptz`; если Postgres не выведет тип, привести: `${now.toISOString()}::timestamptz`.
