# 2.12.0: роли «Редактор» и «Распорядитель доступа» — план

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** добавить роли `editor` (создаёт и правит свои и выданные шаблоны, превью без групп, построение по §19) и `access_manager` (справочники, состав групп, доступ к любому шаблону без его содержимого), с владельцем шаблона и списком редакторов.

**Architecture:** один модуль прав `apps/api/src/modules/access/permissions.ts` (чистые функции + запросы к БД) и три новых preHandler в `makeGuards` (`requireRole`, `requireTemplateEdit`, `requireTemplateOwner`). Маршруты меняют только `preHandler`; бизнес-логика маршрутов не трогается, кроме создания (владелец), списка `scope=edit`, DTO и импорта. В вебе — хук `usePermissions` вместо проверок `role === 'admin'`.

**Tech Stack:** Fastify 5, drizzle-orm/Postgres, zod; React 19 + Gravity UI + react-query; vitest + testcontainers.

**Spec:** `docs/superpowers/specs/2026-10-02-carbone-reports-design.md`, §43 (контекст — §19 доступ, §33 перенос, §38 блокировка правки, §15.1 сессии).

## Решения контроллера (до исполнения)

- **Где проверка прав.** Маршруты конструктора с `:id` получают `preHandler: guards.requireTemplateEdit` (роль `admin`/`editor` + `assertTemplateEdit` по `req.params.id`); создание и импорт — `guards.requireRole('admin', 'editor')`; удаление и `GET/PUT …/editors` — `guards.requireTemplateOwner`; `PUT …/owner`, источники (кроме `options`), пользователи, бэкапы — `guards.requireAdmin` (= `requireRole('admin')`). Внутренние маршруты `/internal/*` OnlyOffice не трогаются.
- **Экспорт** (`POST /api/templates/export`, тело `{ ids }`): `requireRole('admin','editor')` + для `editor` каждый id через `assertTemplateEdit` (первый отказ — его код).
- **`GET /api/templates/:id/access`** открыт тем же, кто может `PUT`: `admin`, `access_manager` — любой; `editor` — через `assertTemplateEdit`.
- **Блокировка правки (§38).** Захват и перехват (`takeover`) — всем, у кого есть `canEditTemplate`; правила самих блокировок не меняются.
- **Превью и `queries/run`** — `requireTemplateEdit`; `assertTemplateAccess` из превью убирается (он был no-op для админа; для редактора превью по §43 не требует групп).
- **`editingBy` в списке.** `toSummary(..., lock)` сейчас заполняет блокировку только для `admin`; в `scope=edit` — для всех, кто видит список (`admin`/`editor`).
- **Права, которые возвращает API.** `TemplateAdminDetails` и элемент `scope=edit` получают `ownerId: string | null`, `canDelete: boolean`, `canManageEditors: boolean` — веб не вычисляет права сам.
- **Импорт.** `previewImport(deps, zip, actor)` и `applyImport(deps, zip, decisions, actor, log)`, где `actor: SessionUser`. Для `editor`: `existing` фильтруется по `canEditTemplate`; `update` с `targetId`, который он не может править, — `403` «нет права на правку шаблона» (проверка до записи файлов и повторно под блокировкой строк); отсутствующая категория не создаётся (`categoryId: null`), в предпросмотре `categorySkipped: true`. Для `admin` — `categorySkipped: false` всегда. Владелец новых шаблонов (`create`/`copy`) — `actor.id` (и для `admin`).

## Review Focus

1. Выданный редактор (не владелец) открывает шаблон, к которому у него нет доступа по группам: `GET /api/templates/:id` отдаёт DTO конструктора (не `404`), превью работает, `POST /api/reports/:id/render` — `404`. Тест — Task 2.
2. Редактора понизили до `user`, пока у него открыт конструктор: следующий же запрос к маршрутам конструктора — `403`, а `GET /api/templates/:id` — `404` или DTO пользователя по §19. Тест — Task 2.
3. Владелец пытается выдать право пользователю с ролью `user` или самому себе — `400`, список не меняется. Тест — Task 3.
4. `access_manager` вызывает любой маршрут содержимого шаблона (`GET /api/templates/:id` в DTO конструктора, `download`, `queries`, `preview`, `editor-config`, `export`) — нет утечки: `403` по роли или DTO пользователя по §19. Тест — Task 3.
5. Редактор загружает архив, где имя совпадает с чужим шаблоном: в предпросмотре `existing` пуст, решение `create` — `409` (имя занято), `copy` — новый шаблон его. Тест — Task 4.
