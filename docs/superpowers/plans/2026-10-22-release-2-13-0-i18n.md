# 2.13.0: локализация интерфейса (этап 1) — план

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** интерфейс и ошибки API на семи языках (`ru`, `en`, `es`, `pt-BR`, `fr`, `de`, `zh-CN`) с выбором языка в профиле и по браузеру, проверкой полноты каталогов в CI и документом `docs/localization.md` о подходе.

**Architecture:** общие каталоги i18next JSON в `packages/shared/src/i18n/<locale>/<ns>.json` и модуль `packages/shared/src/i18n/index.ts` (языки, выбор языка, переводчик, zod-локали). API переводит ошибки по `req.locale` (`X-Locale` → `Accept-Language` → `DEFAULT_LOCALE`); `AppError` несёт ключ и параметры. Веб — `i18next` + `react-i18next`, `ru` в основном бандле, остальные языки — чанки.

**Tech Stack:** i18next, react-i18next (новые зависимости), zod 4 (`z.locales`), Fastify 5, drizzle, React 19 + Gravity UI, vitest.

**Spec:** `docs/superpowers/specs/2026-10-02-carbone-reports-design.md`, §44 (контекст — §43 роли, §15.1 сессии).

## Решения контроллера (до исполнения)

- **Публичный маршрут языка по умолчанию** — `GET /api/i18n` → `{ defaultLocale }` (без входа); `/api/version` закрыт входом и не меняется. Спецификация обновлена.
- **Клиентской проверки zod в вебе нет** (веб не вызывает `parse/safeParse` схем shared) — перевод сообщений zod выполняется только в API; §44.3 об этом выполняется автоматически.
- **Сигнатура ошибок:** `new AppError(code, status, msg: Msg, details?, internal?)`, где `type Msg = { key: string; params?: Record<string, string | number> }`; помощники `badRequest(key, params?, details?)`, `forbidden(key = 'forbidden', params?)`, `notFound(whatKey)` (ключ сущности: `notFound('template')` → `errors:notFound.template`), `conflict(key, params?)`, `unauthorized()`. Ключи — в пространстве имён `errors`, без префикса `errors:` в коде. `err.message` (для журнала) — русский текст: `super(t('ru')(key, params))`.
- **Сообщения схем shared:** `{ message: 'v:invalidId' }` и т. п.; при `ru`-переводе дают прежний русский текст.
- **Перевод полей ошибок `details`**: обработчик переводит `details[].message`, если это ключ `v:…`, иначе — как zod-issue через `zodLocale(locale).localeError(issue)`. Для этого валидационная ошибка Fastify (`hasZodFastifySchemaValidationErrors`) передаёт сырые issues (`err.validation[].params.issue` у `fastify-type-provider-zod` 7 — проверить на месте и записать в отчёт).
- **Порядок работ:** каркас (Task 1) → API-механизм (Task 2) → перевод сообщений API (Task 3) → веб-каркас (Task 4) → строки веба по разделам (Task 5–7) → документ, README, CHANGELOG (Task 8). Проверка «нет кириллицы в коде веба» включается в Task 7, проверка «нет кириллицы в `AppError`» — в Task 3.

## Review Focus

1. Сервер получает `X-Locale: pt-PT` или `Accept-Language: zh-TW,zh;q=0.9` — ответ на `pt-BR`/`zh-CN`, а не на языке по умолчанию. Тест — Task 2.
2. Ошибка с параметром во множественном числе (например, «повторите через {{count}} секунд») на `ru` и `en` даёт правильные формы для 1, 2, 5, 21. Тест — Task 3.
3. Пользователь сменил язык в меню — новый язык применяется без перезагрузки, включая `<html lang>`, даты в таблицах и сообщения ошибок следующих запросов; после перезагрузки страницы язык тот же. Тест — Task 4.
4. Каталог языка не загрузился (чанк недоступен, например после обновления версии на сервере) — интерфейс остаётся на предыдущем языке и показывает ошибку, а не пустые ключи. Тест — Task 4.
5. Длинные переводы (`de`, `fr`) не ломают узкие места — кнопки в диалогах и пункты меню переносятся, а не обрезаются без подсказки. Проверка — скриншоты в Task 7 на `de` (ширина 1280 и 375).
