# Происхождение кода

Пакет `@carbone-reports/carbone` — изменённая копия Carbone Community Edition 3.8.2
(https://github.com/carboneio/carbone, через форк https://github.com/SamRozhkov/carbone, коммит `1df45b5`),
перенесённая в монорепо carbone-reports через `git subtree` вместе с историей.

Лицензия — Carbone Community License (CCL), текст в `LICENSE.md`. Пакет используется только как часть
продукта carbone-reports (CCL 2.1(b), 2.1(d)) и отдельно не распространяется (`"private": true`).
Пользователи carbone-reports уведомляются, что эта часть продукта подчиняется CCL (раздел «Лицензии» README).

## Отличия от апстрима

- Удалена конвертация через LibreOffice (`converter.js`, `converter.py`, `format.js`, опции `convertTo`/`renderPrefix`).
  Документ собирается в формате шаблона; перевод в другие форматы делает OnlyOffice Document Server в API.
- Добавлена `renderBuffer(template, ext, data, options)` — сборка из буфера без временных файлов.
- Перенесён синтаксис бесплатного режима Carbone 5 (итератор `.i`, циклы по массивам строк, `:set`,
  новые форматтеры, поведение отключённых функций) — см. историю коммитов `packages/carbone`.
- Ограничение `:set` и путей `c.`: метки `:set` выполняются предварительным проходом отдельно для каждого
  XML-файла документа, в порядке обработки файлов. `c` общий для всего рендера, поэтому колонтитул
  (`header*.xml` / `footer*.xml`), обработанный раньше `document.xml`, не видит значений, записанных `:set`
  в теле документа. Поведение EE в этом случае не записано.
- Поиск по ключу в пути аргумента (`..actors[id=.actorId].name`) работает только с тегом
  `{o.preReleaseFeatureIn=5002000}` и новее, иначе — ошибка `Forbidden array access…`, как в EE.
  Источник `:set` с `[i, фильтр]` перебирается с фильтром; для EE это не проверено.
  Фильтр без `i` в источнике `:set` (`d.cars[ok=true].qty`) даёт одно значение — первый подходящий элемент,
  как объект-в-массиве в 3.8.2; для EE это не проверено.

- Осознанное отличие от EE (эталон `matrix/tests2/hide-row-hidebegin-at-end-of-prev-row-hideend-at-end-of-row`):
  `hideBegin` в конце предыдущей строки таблицы и `hideEnd` в конце строки дают ошибку
  «Missing at least one showEnd or hideEnd» (EE молча собирает все строки).
- `{o.}` применяется к каждому XML-файлу документа отдельно: опция в одном файле не видна ранее обработанному.
- Воркер сборки не вызывает `carbone.set()`; `renderBuffer` для пропущенных опций берёт глобальные параметры.
- `renderBuffer` для XLSX после сборки возвращает текст ячеек в `sharedStrings.xml` и номера строк и ячеек (`r`),
  которые убирает препроцессор (`preprocessor.finishXlsx`): со встроенными строками OnlyOffice Document Server при
  конвертации теряет все текстовые ячейки, кроме первой. Старый `render()` собирает XLSX как CE 3.8.2.
- 2.2.0: платные функции Carbone EE написаны заново по открытой документации (правило чистой реализации ниже):
  агрегаторы `aggSum` … `cumCountD` и `:count()` — `lib/aggregate.js`, `drop`/`keep` — `lib/drop.js`
  (спецификация carbone-reports §31). `drop` удаляет элементы после сборки XML, поэтому `cum*`, `count()` и итоги
  по `[]` учитывают и строки, удалённые `drop(row)`.
- 2.4.0: изображения из данных (спецификация §32.1) — `lib/media.js` (правила форматов — `lib/media-formats.js`),
  общий разбор XML — `lib/xmltree.js`. Метка, которая занимает весь замещающий текст картинки-заглушки (DOCX, PPTX, XLSX, ODT, ODS, ODP),
  заменяет картинку изображением из data URI (PNG, JPEG, GIF); смешанный текст и значение — обычный текст печатаются
  как в 2.3.0; повторённые циклом картинки получают уникальные id;
  размеры по заголовку файла — библиотека `image-size` 2.0.4 (MIT, https://codeberg.org/image-size/image-size).
  Добавлена `renderBufferWithWarnings(...)` → `{ buffer, warnings }`. Адрес `http(s)://` загружается встроенным
  `fetch` Node (§32.2): только хосты из `imageUrlAllowlist`, без перенаправлений, тайм-аут `imageUrlTimeoutMs`,
  до 4 загрузок одновременно; сбой сети — заглушка удаляется, предупреждение (адрес без query-строки) — в `warnings`.
- 2.4.0: цвета `:color(scope, type)` (спецификация §32.4) — `lib/color.js`; XLSX/ODS — ошибка шаблона. В ODT/ODP
  элемент получает новый автоматический стиль `CRc<n>` (родитель — исходный общий стиль, автоматический стиль файла
  копируется), поэтому, в отличие от EE, нестандартный стиль на элементе заранее не нужен.
- 2.4.0: проверка адресов динамических ссылок и `:defaultURL` (спецификация §32.5) — `lib/links.js`; недопустимый адрес — `#`, а не адрес carbone.io. В отличие от EE (сохраняет только динамическую часть), смешанный адрес `https://site.ru/?id={d.id}` сохраняется целиком: значение метки после статической части кодируется `encodeURIComponent`, метка в самом начале адреса (`{d.base}/items/{d.id}`, без статики перед ней) вставляется как есть, проверяется итоговый адрес.
  Значение, напечатанное в адресе в обход служебного форматтера (после `show()`, `ifEmpty` и других форматтеров,
  обрывающих цепочку), считается статической частью: адрес с ним проверяется и экранируется для XML, но значение
  не кодируется `encodeURIComponent`. Не поддерживаются: форма EE для XLSX без фигурных скобок (`d.url` в адресе
  ссылки — её не отличить от относительной ссылки на файл) и ссылки через поле Word `HYPERLINK` (`w:instrText`) —
  их адрес не проверяется. Адреса с `localhost`, IP-адресом или именем хоста без домена верхнего уровня
  недопустимы (правило домена §32.5) и становятся `#`.
- 2.4.0: штрихкоды `:barcode(тип, опции)` (спецификация §32.3) — в `lib/media.js`, PNG строит `bwip-js`;
  штрихкод вставляется по тем же правилам, что изображение из данных; `barcode` в обычном тексте — ошибка шаблона,
  штрихкоды шрифтом не поддерживаются.
- 2.5.0: нативные диаграммы DOCX и XLSX (спецификация §34.1–34.2) — `lib/charts.js`. Только для книг с диаграммами
  `c:chartSpace` (XLSX и встроенные в DOCX книги) препроцессор помечает строки и ячейки листа служебными атрибутами
  `crRow` (исходный номер строки) и `crCol` (буква столбца); после сборки (`charts.finish`, до изображений) строки
  нумеруются подряд, ячейкам ставится `r` по `crCol` (в строке с повтором `crCol` — цикл по столбцам — `r` не
  ставится, как в 2.4.0), служебные атрибуты снимаются. Диапазон `c:f` строк `s..e`: начало — первая строка
  результата с `crRow = s` (или ближайшим большим), конец — последняя с `crRow = e` (или ближайшим меньшим); пустой
  цикл — диапазон из одной строки, кэш без точек. Кэши `c:strCache`/`c:numCache` строятся из заполненного листа,
  ячейки числовых рядов, похожие на число, становятся числами. Многоуровневые подписи (`c:multiLvlStrRef`),
  `cx:chartSpace`, объединения и внешние ссылки не меняются. Шаблоны без диаграмм собираются как в 2.4.0.
  Вызов добавлен и в старый `render()`.
- 2.5.0: `:html` (спецификация §34.3–34.4) — `lib/html.js` (метки, реестр, загрузка изображений), разбор в
  независимую от формата модель — `lib/html-model.js` (библиотека `htmlparser2`), запись — `lib/html-docx*.js`
  (DOCX) и `lib/html-odt*.js` (ODT). Как изображения 2.4.0: форматтер печатает служебный жетон, асинхронный шаг
  после сборки (до диаграмм) заменяет его XML; `:defaultURL(...)` в цепочке с `:html` становится служебным
  `__htmlUrl` — запасным адресом недопустимых ссылок HTML. Жетон вне текста абзаца — ошибка шаблона «html ставится в
  текст абзаца.»; `:html` — только последним форматтером. Изображения `img` загружаются по правилам §32.1–32.2,
  счётчик байтов отчёта общий с изображениями из данных; неверное или незагруженное изображение пропускается с
  предупреждением, превышение лимитов — ошибка шаблона. DOCX: свойства абзаца метки копируются в блоки (`w:sectPr` —
  только в последний абзац; `w:pStyle` и `w:numPr` метки не переходят в заголовки, списки и таблицы); стиль таблиц
  по умолчанию «Normal Table» пропускается в пользу `TableGrid`; не больше 63 столбцов (лишние ячейки сливаются в
  последнюю, так же в ODT); ссылки HTML внутри гиперссылки шаблона пишутся текстом. ODT: оформление метки
  сохраняется внешним `text:span`, оформление HTML — внутренним с автоматическим стилем `CRh<n>` без свойств,
  заданных меткой; автоматические стили — в том же файле. Работает только через `renderBuffer`: старые `render()` и
  `renderXML` оставляют жетоны. `{o.preReleaseFeatureIn=…}` ни на что не влияет.
- 2.6.0: графики ECharts `:chart` (спецификация §35.1–35.2) — `lib/echarts-render.js`, подключение к изображениям из
  данных — `lib/media.js` (вид `chart`, как штрихкоды). Метка в замещающем тексте картинки-заглушки; значение —
  `{ type, width, height, theme, option }` или описание ECharts с `series`, строка — JSON. ECharts 5 рисует SVG в режиме
  SSR без анимации, resvg-js переводит его в PNG с масштабом 2 шрифтом Noto Sans из `assets/fonts` (шрифты сервера не
  используются; любое семейство из описания рисуется Noto Sans). Размер — `width`/`height` или рамка заглушки в px при
  96 dpi (100–4000), без рамки — 600×400; белый фон по умолчанию. Лимиты: описание до 1 МБ, до 20 рядов и 10 000 точек,
  до 5 с на график (проверяется после каждого этапа: отрисовку прервать нельзя). Ошибки ECharts — «график: …».
  Своё расширение: строка `cr:number:{"decimals":…,"thousands":…,"suffix":…}` в `formatter`/`valueFormatter`
  заменяется функцией формата чисел (её пишет конструктор графиков carbone-reports; EE покажет строку как есть).
  `chart` в обычном тексте — ошибка шаблона «график ставится в замещающий текст картинки».

## Правило чистой реализации

Новые возможности написаны по открытой документации carbone.io и по записанному поведению
Carbone EE 5.15.3 без лицензии (эталоны `test/golden/*.json`). Код из образа `carbone/carbone-ee`
не читался, не извлекался и не копировался.

## Обновление из апстрима

`git subtree pull --prefix=packages/carbone carbone-fork master` (без `--squash`, как и при импорте).
